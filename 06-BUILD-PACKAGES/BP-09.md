CAMPAINER-BUILD-PACKAGE-BP-09-001 — v1.0
Managed Marketing / Media / Lead & Business Realization

BUILD AUTHORITY: NO
RUNTIME AUTHORITY: NO

DERIVES FROM: CAMPAINER-BUILD-PACKAGES-MASTER-001 v1.0 + applicable Canonical Flow / Stage Truth / Contracts / Domain Cores.


0. Purpose and Build Boundary
Implement live managed marketing for ongoing and One-Time campaigns, connecting media/creative/platform state to lead potential, sales handling, capacity/economics and business realization instead of treating Ads Manager metrics as the endpoint.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: A10, B7.
Contracts: C12; live reuse of C10/C11; input to C13.
Primary domain/core ownership: Director frames each decision moment; Media/Budget owns allocation; Advisor recommends/explains; Metrics interprets evidence; Golden Lead owns desirability/fit/serviceability meaning; Context stores live/business state.
Dependencies: BP-00, BP-01, BP-08; BP-06/BP-07 outputs; BP-12 pilot overlay.


2. Functional Requirements
FR-09.1 Detect/receive active Decision Moments from time, spend, performance, lead/business evidence, capacity or risk changes.
FR-09.2 Support Media decisions Add/Hold/Reduce/Reallocate/Test/Wait/Preserve using marginal opportunity, economics, capacity, realization and uncertainty.
FR-09.3 Track remaining budget/time and pacing for both ongoing and one-time runs.
FR-09.4 Trigger Creative refresh/Studio Return when evidence supports it without silently changing Strategy.
FR-09.5 Track Meta live-state issues and route authorized technical changes through BP-08.
FR-09.6 Represent lead/opportunity progression where available: lead→response/contact→qualification→meeting/quote/opportunity→won/lost plus reasons and maturity.
FR-09.7 Represent sales treatment/process interventions separately from lead properties.
FR-09.8 Integrate economics/capacity/contribution/collection/fulfillment when decision-relevant.
FR-09.9 Create user/business Tasks/Interventions/Experiments with before/after lineage and measurement intent.
FR-09.10 Generate Advisor recommendations including Wait/Preserve/Do Nothing.
FR-09.11 Material live/business changes re-enter approval/authorization via C12/C10.
FR-09.12 Preserve Potential Lead Quality ≠ Business Realization Capability ≠ Realized Outcome.


3. Non-Functional / Governance Requirements
Must operate with partial/maturing data; no universal KPI threshold or auto-scale rule; decision timestamps and evidence maturity explicit; high-volume events summarized without losing lineage; managed decisions versioned; Human Review for material budget/live/business interventions in pilot.


4. Conceptual Data Objects and Relationships
ManagedDecisionMoment; MediaAllocationDecision; Spend/PacingState; Lead; ContactAttempt/Response; QualificationEvidence; Meeting/Quote/Opportunity; Outcome; SalesTreatment; CapacityState; EconomicsSnapshot; BusinessIntervention; Experiment/Test; ManagedRecommendation.

6. API / Integration Requirements
ingestCampaign/lead/business events; createDecisionMoment; propose/recordMediaDecision; createTask/Intervention/Test; updateLeadProcessState; updateCapacity/Economics; requestCreativeReturn; requestAuthorizedLiveChange; handoffMatureEvidenceToMeasurement.


7. Prompt / Model / Tool Responsibilities
Models may diagnose current bottleneck and propose media/creative/sales/business actions using governed evidence. They cannot label unsold leads as low quality by default, infer causality from after-change results, auto-scale on average KPI or execute material changes without authority.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
Advisor operating workspace should surface current goal/progress, key active decision, spend/time, media/creative status, lead/business realization funnel, Tasks/Tests, what is waiting/unknown and recommended next action. Avoid dashboard-first overload; focus on decision moments.


9. Authority / Consent / Human Review Gates
Recommendations/tests/tasks do not grant live authority. Material budget, campaign, creative or business interventions require appropriate approval/authorization and Human Review in pilot; user-owned business tasks may be assigned without pretending Campainer executed them.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Project current campaign state, spend/time, lead/opportunity progression, sales treatment, capacity/economics, relevant goals/commitments and only domain knowledge needed for current bottleneck. Do not dump entire CRM/History.


11. Evidence / Event / Readback Requirements
Campaign/media/creative changes; lead process/treatment events; user/business interventions; outcomes; spend; capacity/economics snapshots; concurrent changes; decision/review/authority lineage.


12. Metrics / Measurement Requirements
Media delivery/cost metrics plus deepest reliable downstream outcomes; response/contact/qualification/meeting/quote/won/lost; contribution/collection/fulfillment where available; maturity/missingness visible. Attribution/incrementality handled in BP-10.


13. Failure / Recovery / Rollback / Semantic Return
Missing downstream data→Unknown/task, not low-quality label; stale live state→refresh; capacity problem→business recommendation/Wait rather than blind scaling; creative issue→Studio Return; unauthorized material change→block; conflicting evidence→Director/Advisor reopen.


14. Security / Privacy / Multi-Business Isolation
Lead/customer data scoped and access-controlled; minimize PII in model projections; multi-business isolation; sales/business intervention evidence accessible only to authorized user/reviewer; follow privacy retention hooks.


15. Tests
Good lead+poor response not classified as bad lead; poor lead+good salesperson separated; capacity constraint prevents automatic scale; average KPI alone cannot auto-change budget; one-time remaining time affects decision; unauthorized change blocked; task/intervention lineage survives; Return to Studio/Strategy correct.


16. Acceptance Criteria
AC-09.1 Managed decisions integrate media and business-realization evidence.
AC-09.2 Potential Quality, Realization Capability and Outcome are separately observable.
AC-09.3 Sales treatment is represented as process/treatment, not lead property.
AC-09.4 Wait/Preserve/Do Nothing are valid outputs.
AC-09.5 Material changes enter authority chain.
AC-09.6 Evidence can hand off to BP-10 with intervention/change lineage.


17. Migration / Compatibility
Existing campaign metrics and CRM events may be imported with explicit source/maturity; historical Won/Lost/lead labels must not be assumed to represent pure lead quality.


18. Deferred / Open Decisions
CRM/provider integrations, exact lead/process schemas, media pacing algorithms, Golden Lead predictive scores, response-time thresholds, sales qualification taxonomy, economics/ERP integration depth.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.


19. Traceability
Golden Lead + Media/Budget + Metrics + Context + Advisor/Director Cores → Stage Truth A10/B7 → C12/C10/C11/C13 input → BP-09.
Every implemented requirement must map back to approved Truth/Core/Flow/Stage/Contract and forward to a test/evidence requirement.


20. Build Authority Gate
This package remains NON-EXECUTABLE until the Product Owner explicitly grants Build Authority to this package or to a governed release wave that names it.
