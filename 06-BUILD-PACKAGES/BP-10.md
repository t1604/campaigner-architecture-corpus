0. Purpose and Build Boundary
Implement the evidence-to-interpretation-to-learning path that distinguishes raw observations, metric meaning, outcome maturity, attribution, incrementality and causal limits, then produces scoped Learning Candidates and the next professional decision without self-promoting results to truth.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: A11, B9.
Contracts: C13, C15; receives closure evidence from C14/BP-11.
Primary domain/core ownership: Metrics owns measurement meaning/permitted inference; Learning/Evolution owns candidate lifecycle; Context owns local outcome history; Advisor/Director own next professional decision.
Dependencies: BP-00, BP-01, BP-09; BP-11 for final One-Time closure evidence.


2. Functional Requirements
FR-10.1 Ingest governed evidence package with baseline/current state, exposure/treatment/intervention history, concurrent changes, outcomes, spend and missingness/maturity.
FR-10.2 Distinguish Raw Data, Metric, Proxy, Outcome and estimand/decision target as needed.
FR-10.3 Represent pending/censored/missing/unmatched states explicitly.
FR-10.4 Produce Measurement Interpretation stating what happened, what may be inferred, causal/attribution class, uncertainty and what remains Unknown.
FR-10.5 Separate Attribution from Incrementality; no after-change=caused-by-change shortcut.
FR-10.6 Use deepest reliable outcome appropriate to decision rather than optimizing media proxy by default.
FR-10.7 Create Learning Candidate only when warranted, with scope/transferability/contradiction state.
FR-10.8 Support candidate dispositions Keep/Strengthen/Split/Demote/Reopen/Retire/New Candidate.
FR-10.9 Update local Context separately from general Knowledge candidate.
FR-10.10 Generate user-facing What Works/What Learned/Goal & Progress with uncertainty.
FR-10.11 Route Next Decision/Reopen to correct Stage/domain, not generic beginning.
FR-10.12 Support late-maturing outcome/corrected-data reopen.


3. Non-Functional / Governance Requirements
Measurement semantics versioned; denominator/source/maturity visible; no hidden global truth score; causal claims require explicit evidence class; learning candidates cannot self-promote; late data must be mergeable without rewriting history; Human Review on material causal interpretation/broader reuse in pilot.


4. Conceptual Data Objects and Relationships
MeasurementDefinition; MetricObservation; OutcomeObservation; Exposure/Treatment; Intervention; MeasurementInterpretation; CausalClass; Missingness/MaturityState; LearningCandidate; CandidateDisposition; NextDecisionRef; GoalProgress.

6. API / Integration Requirements
ingestMeasurementEvidence; resolveMetricMeaning; compute/recordMaturity; createMeasurementInterpretation; create/updateLearningCandidate; recordCandidateDisposition; updateLocalContextFromResult; proposeNextDecision/Reopen; attachLateOutcome/Correction.


7. Prompt / Model / Tool Responsibilities
Models may summarize evidence and draft interpretations within explicit Metrics semantics, and propose candidate learning/next decisions. They may not infer causal effect merely from correlation/timing, self-promote learning, or generalize across businesses without scope/validation.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
User-facing summary prioritizes what happened, what it likely/does not prove, business outcome, what was learned, what remains unknown and recommended next decision. Internal reviewer view shows sources, maturity, missingness, causal class and candidate lifecycle.


9. Authority / Consent / Human Review Gates
Measurement/learning creates no execution authority. Any next action re-enters appropriate approval/authorization. Material causal claims and broader candidate reuse/promotion require Human Review/governed authority.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Metrics receives intervention/change history, baseline/current state, outcomes, exposure/treatment, concurrent changes and source/maturity. Learning receives Metrics Interpretation, not raw data alone. Advisor receives decision-relevant interpretation/candidate state.


11. Evidence / Event / Readback Requirements
Measurement definitions, source/matching/maturity, raw/derived observations, interpretation version, causal/attribution limits, Learning Candidate evidence/scope/disposition, Context update refs and next-decision linkage.


12. Metrics / Measurement Requirements
This package owns semantic measurement itself. System-quality metrics: coverage, missingness, outcome maturity, matched downstream outcome rate, causal-claim review overrides, candidate reopen/demotion, late-data corrections.


13. Failure / Recovery / Rollback / Semantic Return
Insufficient maturity/coverage→Wait/Unknown, not forced conclusion; contradictory results→candidate scope split/reopen; corrected data→new interpretation version; causal ambiguity→descriptive/attribution result only; downstream route unavailable→Next Decision remains pending.


14. Security / Privacy / Multi-Business Isolation
Outcome/lead/economic data access minimized and business-scoped; aggregate learning strips unnecessary identifiers; cross-business analysis governed; sensitive outcome data retention follows privacy controls.


15. Tests
After-change result cannot be labeled causal without supported class; attribution and incrementality stay separate; censored outcome remains pending; local result does not auto-promote globally; candidate can demote/reopen; late Won/Lost changes interpretation version; next decision routes to owning Stage.


16. Acceptance Criteria
AC-10.1 Every material interpretation states data maturity/limits.
AC-10.2 Result, attribution and causal inference are separate.
AC-10.3 Learning Candidate is distinct from promoted Knowledge/Truth.
AC-10.4 Local Context update and general learning are separate paths.
AC-10.5 User receives understandable summary rather than Ads Manager dump.
AC-10.6 Next Decision/Reopen targets correct professional owner.


17. Migration / Compatibility
Legacy metrics should be imported with source/definition and unknown maturity where necessary; historical 'winning' creatives/strategies remain observations/candidates, not permanent truth.


18. Deferred / Open Decisions
Exact metric ontology, experiment/sample-size rules, attribution models, incrementality methods, calibration thresholds, CV-007 schema, learning-transfer algorithms.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.

Every implemented requirement must map back to approved Truth/Core/Flow/Stage/Contract and forward to a test/evidence requirement.
