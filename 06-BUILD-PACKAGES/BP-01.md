Knowledge + Context Projection + Director/Advisor Decision Runtime

0. Purpose and Build Boundary
Implement the professional decision runtime that converts a Moment/Decision Need into minimum-sufficient Context and Knowledge projections and supports Director framing plus Advisor judgment without whole-corpus dumping or hidden truth promotion.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: Reusable across A1, A2, A4, A5, A10, A11, B1, B2, B7, B9 and any later decision moment.
Contracts: Supports C02, C05, C12, C13, C15, C16 and the semantic envelope used by all contracts.
Primary domain/core ownership: Director owns bounded Decision Frame; Advisor owns professional judgment/explanation; Context owns local truth; Knowledge/Evidence owns claims/priors/evidence/unknown/freshness; domain owners consume projections.
Dependencies: BP-00 required. Professional Knowledge Foundation and active Domain Cores are source authority for professional content.


2. Functional Requirements
FR-01.1 Create/update bounded Decision Need with subject, purpose, owner domains, dependencies and breakers.
FR-01.2 Request minimum-sufficient Context Projection from scoped local truth.
FR-01.3 Derive Knowledge Need from Decision Need rather than generic search.
FR-01.4 Retrieve/select by domain, scope, status/maturity and freshness.
FR-01.5 Produce Knowledge Projection with supportive and contradictory evidence, Priors and Unknowns.
FR-01.6 Support Advisor outputs: question, explanation, recommendation, task, test/intervention candidate, wait/preserve/do-nothing.
FR-01.7 Ask/collect only when the expected answer can materially change a current/future decision.
FR-01.8 Record governed usage trace linking active knowledge/evidence to decision/output without chain-of-thought.
FR-01.9 Accept user correction and contradictions without overwriting lineage.
FR-01.10 Return safely when required knowledge is missing/stale or local truth conflicts.


3. Non-Functional / Governance Requirements
Projection latency must be compatible with interactive Advisor use; retrieval must expose source/status/freshness; no source may be treated as truth by rank alone; whole corpus must not be placed in default model context; usage trace must be reconstructable; prompts/model changes must be versioned; failure must degrade to explicit Unknown/Need rather than fabrication.


4. Conceptual Data Objects and Relationships
DecisionNeed; ContextProjection; KnowledgeNeed; KnowledgeItemRef; KnowledgeProjection; ProfessionalOutput; Question/DataNeed; UsageTrace; ContradictionRef; CorrectionRef. DecisionNeed references active scope and target Stage/moment; projections reference source truth/knowledge rather than duplicating ownership.

6. API / Integration Requirements
createDecisionNeed; getContextProjection; deriveKnowledgeNeed; retrieveKnowledgeProjection; submitProfessionalOutput; recordCorrection; createTargetedQuestion; close/reopen DecisionNeed; attachUsageResult. Retrieval interface must support domain/scope/freshness/status filters and evidence provenance.


7. Prompt / Model / Tool Responsibilities
Models may propose Decision Frames, synthesize projections, generate questions/recommendations and explain tradeoffs using governed inputs. Director model may not become permanent state owner; Advisor model may not mint local facts, authority or causal truth. Outputs must separate supported conclusion, assumptions, Unknowns and what could change the recommendation.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
Advisor surface must show one coherent relationship, targeted questions only, visible assumptions/Unknowns where material, user correction affordances, recommendation rationale, tasks/tests/wait states and progress. Internal operator/reviewer surface may inspect projection sources/status and usage trace.


9. Authority / Consent / Human Review Gates
Professional recommendation has no execution authority. Material pilot recommendations and causal interpretations route through Human Review. User answers may establish local claims only through Context rules; research retrieval never grants local truth.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Context interface returns only decision-relevant local truth/unknown/history. Knowledge interface returns only relevant professional claims/priors/evidence/counterevidence with scope/freshness/maturity. Role projection must trim content further for Creative, Media, Meta, Metrics, etc.


11. Evidence / Event / Readback Requirements
Record source refs, projection versions, contradictions/unknowns, material user corrections, Decision Need state, professional output version and usage trace. Later result can be linked back without claiming causal influence merely because knowledge was present.


12. Metrics / Measurement Requirements
Runtime quality: question usefulness, retrieval relevance coverage, stale/missing knowledge events, contradictions surfaced, user correction rate, whole-corpus bypass violations, trace completeness. Do not optimize professional truth to engagement metrics.


13. Failure / Recovery / Rollback / Semantic Return
If projection unavailable, return explicit missing need and use responsible alternative only if decision remains supportable. If knowledge contradicts local evidence, preserve both and route to decision owner. If retrieval fails, no invented substitute. Reopen Decision Need on material correction/new evidence.


14. Security / Privacy / Multi-Business Isolation
Projection requests inherit BP-00 scope/least-privilege. Knowledge access can be broader than local Context but local data never crosses business scope automatically. Sensitive Context fields are withheld unless decision-relevant and authorized.


15. Tests
Unit: DecisionNeed lifecycle, projection minimization, freshness filtering, contradiction preservation. Integration: Context+Knowledge→Advisor; user correction→revised projection; stale Meta knowledge→Return. E2E: short diagnosis and one-time intake show different projection needs. Golden tests ensure Prior never becomes Local Fact.


16. Acceptance Criteria
AC-01.1 Material recommendation can be reconstructed from governed projections and evidence refs.
AC-01.2 Whole-corpus loading is not the default path.
AC-01.3 User is not re-asked for known/correctly obtainable information without decision value.
AC-01.4 Contradictory evidence and Unknowns remain visible to professional judgment.
AC-01.5 Local correction updates Context lineage and causes targeted reopen when material.
AC-01.6 No model output directly becomes authority or promoted truth.


17. Migration / Compatibility
Existing long-form prompts/corpora may be retained as source material but must be decomposed or indexed for governed retrieval. Existing user context needs projection adapters before direct consumption by new decision runtime.


18. Deferred / Open Decisions
Final vector/search architecture, embedding/model vendor, Knowledge Item exact schema/status enums, retrieval ranking/calibration, caching strategy, prompt templates, token budgets, CV-007 data contract.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.
