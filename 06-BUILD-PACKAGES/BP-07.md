CAMPAINER-BUILD-PACKAGE-BP-07-001 — v1.0
Campaign Readiness & User Review
STATUS: OWNER-APPROVED BUILD REQUIREMENTS

DERIVES FROM: CAMPAINER-BUILD-PACKAGES-MASTER-001 v1.0 + applicable Canonical Flow / Stage Truth / Contracts / Domain Cores.


0. Purpose and Build Boundary
Implement the professional readiness layer that combines Strategy/Brief, Studio, Media/Budget, Meta capability, Measurement and Business Realization readiness into an exact reviewable campaign package, then collects scoped User Approval without conflating it with Authorization.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: A7, A8, B5 and equivalent One-Time readiness before B5.
Contracts: C08; prepares C09.
Primary domain/core ownership: Director integrates readiness; Media owns allocation judgment; Meta owns current capability/state; Metrics owns readiness/measurement meaning; Advisor explains; User owns approval.
Dependencies: BP-00, BP-01, BP-04/BP-05 and BP-06.


2. Functional Requirements
FR-07.1 Assemble versioned CampaignPackage from approved Strategic Intent/One-Time Brief and Studio outputs.
FR-07.2 Produce Media/Budget recommendation using marginal opportunity, economics, capacity, uncertainty and alternative resource use; no average-KPI controller.
FR-07.3 Query current Meta capability/permissions/state with freshness markers; capability is input only.
FR-07.4 Confirm measurement intent, Baseline/readback readiness and downstream lead/business-realization observability where relevant.
FR-07.5 Classify manageable gaps into Start Now / Start+Parallel / Responsible Alternative / Wait / Preserve / genuine Stop.
FR-07.6 Produce exact UserReviewPackage: what will run, audience meaning, offer/CTA/destination, budget envelope, time/window, creative/assets, assumptions/risks/Unknowns, measurement intent and approval scope.
FR-07.7 Record approve/reject/request-change against exact package version.
FR-07.8 Route material requested change to owning Stage/domain rather than mutate package silently.
FR-07.9 Handoff approved exact version to Authorization gate with explicit 'authorization absent' state.


3. Non-Functional / Governance Requirements
Meta/readiness data must carry freshness; package version immutable after approval (new version for changes); approval UX must be understandable; readiness decision traceable to domain contributions; no hidden hard-stop checklist where responsible alternative exists; Human Review for material Media/Readiness/Approval decisions in pilot.


4. Conceptual Data Objects and Relationships
CampaignPackage; ReadinessAssessment; DomainReadinessContribution; MediaPlan; BudgetEnvelope; MetaCapabilitySnapshot; MeasurementReadiness; BusinessRealizationReadiness; Gap/Dependency; UserReviewPackage; ApprovalRecord.

6. API / Integration Requirements
assembleCampaignPackage; computeDomainReadiness; requestFreshMetaSnapshot; createMediaPlan; evaluateMeasurementReadiness; createUserReviewPackage; approve/reject/requestChange; returnToOwningStage; handoffApprovalToAuthorization.


7. Prompt / Model / Tool Responsibilities
Models may synthesize domain contributions into explanation and surface tradeoffs/gaps. Media model cannot assume Meta capability; Meta model cannot decide Strategy/Budget; Advisor model cannot treat approval as Authorization. Human Review validates material readiness/allocation.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
Review workbench shows exact package version, creative preview, intended audience/geo meaning, offer/CTA, budget/time, measurement plan, assumptions/risks and manageable gaps. Approval controls are explicit and separate from later launch authorization.


9. Authority / Consent / Human Review Gates
Readiness grants no authority. User Approval applies only to exact reviewed package version/scope. Approval ≠ Authorization. Material Media/Budget and campaign approval decisions are Human Reviewed in pilot.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Receive only approved Strategic Intent/Brief, Brand/Creative package, economics/capacity/Golden Lead context, relevant Meta snapshot and measurement state. Each domain receives minimum-sufficient projection.


11. Evidence / Event / Readback Requirements
Store domain readiness contributions, Media decision basis, Meta snapshot/freshness, measurement readiness, gaps/dependencies, package versions, user corrections and approval/rejection/defer records.


12. Metrics / Measurement Requirements
Readiness gaps by type, stale-capability returns, approval change reasons, media-decision review overrides and measurement-readiness coverage. These diagnose process quality, not campaign causal success.


13. Failure / Recovery / Rollback / Semantic Return
Stale Meta state→refresh/Return; missing asset→Studio task/alternative; budget/economics mismatch→Media/Strategy Return; measurement gap→parallel task/alternative where responsible; material user requested change→new upstream version; no silent fallback.


14. Security / Privacy / Multi-Business Isolation
Review package scoped to correct business/campaign; permissions/capability data least-privilege; no disclosure of unrelated user context; approval actor identity verified.


15. Tests
Stale Meta snapshot cannot close readiness; average CPL alone cannot drive allocation test; missing noncritical asset allows alternative; genuine blocker produces Stop; approved version immutable; requested change routes upstream; approval creates no authorization.


16. Acceptance Criteria
AC-07.1 Every campaign reaching review has a versioned package with Strategy/Brief, creative, budget/time and measurement intent.
AC-07.2 Domain readiness is explicit and traceable.
AC-07.3 Responsible alternatives prevent false dead ends.
AC-07.4 User can understand and correct what will run.
AC-07.5 Approval is linked to exact version/scope.
AC-07.6 Approved package carries zero live authority until C09.


17. Migration / Compatibility
Existing campaign drafts/approvals must be versioned on import; historical 'approved' flags cannot be treated as launch authorization.


18. Deferred / Open Decisions
Exact readiness enum/score (if any), Media allocation algorithms/thresholds, Meta capability fields/freshness windows, review component layout, bundled approval classes.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.


19. Traceability
Media/Meta/Metrics/Golden Lead/Brand/Creative boundaries → Stage Truth A7/A8/B5 → C08/C09 boundary → BP-07.
Every implemented requirement must map back to approved Truth/Core/Flow/Stage/Contract and forward to a test/evidence requirement.


20. Build Authority Gate
This package remains NON-EXECUTABLE until the Product Owner explicitly grants Build Authority to this package or to a governed release wave that names it.
