Shared Studio: Brand Assets Room + Creative Room

0. Purpose and Build Boundary
Implement one Studio product place containing two professionally separate rooms: Brand Assets and Campaign Creative. The package must let both ongoing and One-Time paths reuse the same Studio while preserving Brand Core ≠ Creative Core and allowing Semantic Return between rooms.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: A6, B4.
Contracts: C06 Strategic Intent→Studio; C07 One-Time Brief→Studio; C16 Return.
Primary domain/core ownership: Brand/Brand Assets owns Brand Truth/assets/readiness/rights; Creative owns representation/concept/execution; Advisor/Director retain strategic meaning; Experience owns the unified Studio experience.
Dependencies: BP-00, BP-01, plus BP-04 or BP-05 depending branch.


2. Functional Requirements
FR-06.1 Present Studio as one product place with two rooms and persistent branch/campaign context.
FR-06.2 Brand Assets room supports business/brand scope, upload/import, source/master/version lineage, proof assets, rights/consent/provenance/restrictions/readiness and missing-asset tasks/alternatives.
FR-06.3 Generate Minimum-Sufficient Brand Snapshot for a campaign without forcing full brand-system completion.
FR-06.4 Creative room receives Strategic Intent or One-Time Brief plus Brand Snapshot through C06/C07.
FR-06.5 Creative workflow represents Creative Job→Representation→Concept→Execution and professionally justified variants.
FR-06.6 External/AI production can be coordinated without transferring creative judgment.
FR-06.7 Creative cannot silently change Strategy/Brand Truth/protected claims; Brand cannot silently change Strategy.
FR-06.8 Creative may Return to Brand/Advisor when proof/asset/rights/meaning is insufficient; Brand may Return to Advisor/Director when requested expression implies repositioning.
FR-06.9 Campaign evidence may create Brand Change Candidate, never automatic Brand Truth change.
FR-06.10 One-Time users can use available assets or create minimum needed assets without building a full permanent brand system.


3. Non-Functional / Governance Requirements
Asset lineage and rights state must be durable; large media storage must be provider-abstracted; room switching must preserve context; creative generation must be reproducible/versioned enough for review; no cross-business asset inheritance by default; support human review of material claim/brand/creative meaning.


4. Conceptual Data Objects and Relationships
BrandScope; BrandTruthItem; Asset; AssetVersion; AssetSource/Master; Rights/Consent/Provenance; ProofAsset; BrandSnapshot; CreativeJob; Representation; Concept; CreativeExecution; Variant; ProductionJob; BrandChangeCandidate.

6. API / Integration Requirements
list/upload/import/version assets; set rights/provenance; create Brand Snapshot; request missing asset/task; create Creative Job from C06/C07; create concepts/executions/variants; request production; submit Creative/Brand Return; publish review package downstream.


7. Prompt / Model / Tool Responsibilities
Creative models may ideate representations/concepts/executions inside handed-off intent and Brand constraints. Brand assistant may organize assets/readiness but cannot invent Brand Truth. External generation tools receive minimum-sufficient prompt/context; prompts must preserve protected claims and rights constraints.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
Single Studio shell with two clear rooms/tabs: נכסי המותג and יצירת הקריאייטיב. Show asset library/readiness/rights, campaign-specific needed assets, creative concepts/variants, version history, review state and Return/task notices. User should not perceive two disconnected products.


9. Authority / Consent / Human Review Gates
Material Brand/claim changes and material Creative meaning decisions require Human Review in pilot and user approval where Stage Truth requires. Provider/AI capability never grants rights or approval. Asset upload is not permission to use if rights/consent are unresolved.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Creative receives Strategic Intent/One-Time Brief, buyer/audience meaning, Must-Believe/Proof Need, offer/CTA, campaign constraints, Brand Snapshot and platform/measurement constraints only as needed. It never receives whole CRM/Context by default.


11. Evidence / Event / Readback Requirements
Asset source/version/rights/provenance; Brand Snapshot version; Creative Job input contract; concept/execution/variant lineage; provider production receipt; review decisions; Semantic Returns; Brand Change Candidate references.


12. Metrics / Measurement Requirements
Asset readiness/gap resolution, creative review/revision counts, production failures, variant test linkage and later creative outcome evidence. Campaign performance does not directly update Brand Truth.


13. Failure / Recovery / Rollback / Semantic Return
Missing asset→task/alternative/parallel route, not automatic Stop; unresolved rights→block use of affected asset, not whole Studio when alternatives exist; provider failure→retry/alternative production if semantically equivalent; meaning change→Semantic Return.


14. Security / Privacy / Multi-Business Isolation
Business-level asset isolation; signed/controlled media access; provider sharing minimization; rights/provenance visibility; no cross-business inheritance without explicit relation; sensitive source files access-controlled.


15. Tests
Ongoing and One-Time both enter same Studio; rooms remain separate ownership; asset without rights cannot be used; missing asset can take responsible alternative; Creative strategy-changing request triggers Return; business A assets never appear in B; provider failure preserves semantic intent/version.


16. Acceptance Criteria
AC-06.1 UI is one Studio with two rooms.
AC-06.2 Brand and Creative objects/authority remain distinct.
AC-06.3 Both branches can create campaign-ready creative.
AC-06.4 Rights/provenance/readiness are traceable.
AC-06.5 Missing ordinary assets do not create false dead end.
AC-06.6 Any required change to Strategy/Brand Truth triggers correct Return rather than silent substitution.


17. Migration / Compatibility
Existing creative/brand files should be cataloged with unknown rights/provenance rather than assumed ready; historical Studio artifacts remain lineage; existing multi-business assets must be explicitly assigned to scope.


18. Deferred / Open Decisions
Storage/CDN/provider choices, exact media formats/limits, final external production vendors, generation model choice, variant counts, rights/legal policy details, final Brand Truth schema.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.


19. Traceability
Brand + Creative Cores → Canonical Flow Studio decision → Stage Truth A6/B4 → C06/C07/C16 → BP-06.
Every implemented requirement must map back to approved Truth/Core/Flow/Stage/Contract and forward to a test/evidence requirement.


20. Build Authority Gate
This package remains NON-EXECUTABLE until the Product Owner explicitly grants Build Authority to this package or to a governed release wave that names it.


21. OWNER-APPROVED EXTERNAL-REVIEW REMEDIATION — STUDIO SCOPE NORMALIZATION
21.1 BP-06 consumes BP-00 v1.1 canonical ScopeRef for every Asset, BrandSnapshot, CreativeJob, CreativeExecution and ProductionJob. Draft business_id/campaign_ref fields are implementation conveniences only and cannot become parallel ownership truth.
21.2 For an unattached One-Time Campaign, campaign-specific assets/creative may belong to the explicit ONE_TIME_CAMPAIGN ScopeRef without requiring a Business. Such assets are campaign-scoped and do not become permanent Business Brand Assets by default.
21.3 Promotion/attachment of a campaign-scoped asset into a Business/Brand scope requires an explicit governed relationship preserving source/version/rights/provenance; no implicit re-parenting or cross-business inheritance is permitted.
21.4 A permanent Brand Truth item or Business Brand Asset remains Business-scoped. One-Time use may reference it only through an explicit allowed relationship and does not change ownership.
21.5 Tests: One-Time-without-Business enters Studio and produces campaign-scoped creative; Business A asset never appears in unrelated One-Time/Business B scope; explicit attachment preserves provenance and rights; campaign asset does not silently become Brand Truth; ambiguous scope blocks use.
21.6 Acceptance additions. AC-06.7 Studio ownership is expressed through canonical ScopeRef across both branches. AC-06.8 Unattached One-Time scope is buildable without weakening multi-business isolation. AC-06.9 Asset attachment/promotion is explicit and provenance-preserving.
