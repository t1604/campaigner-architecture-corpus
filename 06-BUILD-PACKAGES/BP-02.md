CAMPAINER-BUILD-PACKAGE-BP-02-001 — v1.0
Entry & Branch Routing

0. Purpose and Build Boundary
Implement the shared entry point that exposes Business/Ongoing and One-Time as explicit user choices at the point where Short Diagnosis begins, while preserving one continuous Advisor and preventing hidden branch classification or accidental authority.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: ENTRY — Branch Selection.
Contracts: C01 Branch Choice Handoff.
Primary domain/core ownership: Experience owns interaction; Advisor owns continuity/explanation; User owns branch choice; Context is conditional for known scope.
Dependencies: BP-00 and minimal BP-01 projection support.


2. Functional Requirements
FR-02.1 Present two explicit entry actions: Business/Ongoing and One-Time.
FR-02.2 One-Time action routes directly to B1 without initializing A1 Short Diagnosis.
FR-02.3 Record explicit branch choice and active scope.
FR-02.4 If existing user has multiple businesses, project active Business only when relevant and require clear switching.
FR-02.5 If later evidence indicates mismatch, present Advisor explanation and user choice; never silently convert branch.
FR-02.6 Preserve same Advisor identity across both branches.


3. Non-Functional / Governance Requirements
Entry must be fast, accessible and reversible; no unnecessary Knowledge activation; branch state must be deterministic and auditable; route change must preserve prior history.


4. Conceptual Data Objects and Relationships
BranchChoice; ActiveScopeRef; EntrySession. BranchChoice references user, selected branch, optional business scope and timestamp/version.


5. Proposed Concrete Schemas — DRAFT / NOT APPROVED
entry_session(id,user_id,active_business_id,started_at); branch_choice(id,entry_session_id,branch_kind,chosen_by,chosen_at,supersedes_id). branch_kind enum DRAFT: BUSINESS_ONGOING | ONE_TIME.
Schema rule: IDs, fields, enums, indexes and persistence mechanics remain DRAFT until separately approved. No inferred field is canonical merely because it appears here.


6. API / Integration Requirements
getEntryState; selectBranch; switchActiveBusiness; reopenBranchChoice; handoffToA1/B1. selectBranch must not create execution authorization.


7. Prompt / Model / Tool Responsibilities
Advisor may explain differences and suggest reconsideration if user intent appears mismatched, but model cannot override branch choice or classify the user into another branch automatically.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
At Short Diagnosis entry show main Business/Ongoing start action plus distinct One-Time button/choice labeled in user language. If multi-business, show active business clearly without turning entry into a dashboard. Preserve Advisor continuity and allow back/reconsider choice.


9. Authority / Consent / Human Review Gates
Branch choice is user choice only. It confers no payment, approval, authorization or Meta authority. Forced branch migration is prohibited.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Only user identity and active Business scope when already known/useful; no deep Context or broad Knowledge projection by default.


11. Evidence / Event / Readback Requirements
Record selected branch, active scope reference, superseded prior branch choice and any Advisor-suggested reconsideration accepted/rejected.


12. Metrics / Measurement Requirements
Operational: branch completion, branch changes, mistaken-route returns, multi-business scope errors. Do not optimize choice framing to maximize paid conversion at expense of professional fit.


13. Failure / Recovery / Rollback / Semantic Return
If active Business is ambiguous, request selection only when needed. If branch state cannot persist, do not start downstream stage with guessed state. Mismatch returns to entry choice with prior work preserved.


14. Security / Privacy / Multi-Business Isolation
No cross-business context exposure on entry; business list limited to user's authorized businesses; branch choice history private to authorized user/operator.


15. Tests
E2E Business button→A1; One-Time button→B1 with zero A1 initialization; multi-business active scope test; branch reconsideration preserves history; no authority record created by branch choice.


16. Acceptance Criteria
AC-02.1 One-Time is a separate visible button/choice at the Short Diagnosis entry.
AC-02.2 One-Time reaches B1 without business diagnosis.
AC-02.3 User choice cannot be silently overridden.
AC-02.4 Same Advisor identity persists.
AC-02.5 Active Business scope is unambiguous when relevant.
AC-02.6 Entry produces no live-action authority.


17. Migration / Compatibility
Existing Short Diagnosis entry should be adapted rather than duplicated; historical route-selection UX should be preserved as lineage and removed only where superseded by canonical Entry.


18. Deferred / Open Decisions
Exact visual placement/copy, mobile layout, whether returning users see recent one-time campaigns, analytics events beyond governance needs.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.


19. Traceability
Canonical Flow Entry + One-Time Flow entry decision → Entry Stage Truth → C01 → BP-02 FR/AC/tests.
Every implemented requirement must map back to approved Truth/Core/Flow/Stage/Contract and forward to a test/evidence requirement.


20. Build Authority Gate
This package remains NON-EXECUTABLE until the Product Owner explicitly grants Build Authority to this package or to a governed release wave that names it.
