0. Purpose and Build Boundary
Implement the cross-cutting controlled-pilot safety and observability overlay applied to every Build Package so Campainer can be reviewed, audited, stopped, corrected and recovered even when individual components fail.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: Cross-cutting overlay for ENTRY, A1–A11 and B1–B9.
Contracts: Human Review overlay on all material contracts; especially C09–C16.
Primary domain/core ownership: Does not create a new professional Core. Governance/control implementation supports all owners; BP-00 authority/lineage foundation is reused.
Dependencies: BP-00 required; overlays BP-01–BP-11. No package may receive Controlled Pilot Build Authority without applicable BP-12 controls.


2. Functional Requirements
FR-12.1 Route 100% of material pilot professional/execution decisions through Human Review according to Stage/Contract class.
FR-12.2 Record reviewer identity, subject/version, decision, notes/evidence and outcome.
FR-12.3 Provide trace explorer sufficient to reconstruct governed inputs, decisions, authority, execution, readback and result without private chain-of-thought.
FR-12.4 Provide feature/config gates to disable material write paths or packages independently.
FR-12.5 Enforce multi-business isolation and run explicit isolation checks.
FR-12.6 Provide least-privilege permission controls and credential/role boundaries.
FR-12.7 Implement privacy/sensitive-data handling hooks, deletion/retention hooks and legal gates required for pilot.
FR-12.8 Observe errors, timeouts, retries, partial state, recovery/rollback and Semantic Returns.
FR-12.9 Provide Meta read-only/live-state validation gate before/alongside approved write capability.
FR-12.10 Maintain QA golden cases for both branches and critical edge cases.
FR-12.11 Provide operator kill/hold controls for controlled pilot when material risk/uncertainty arises.
FR-12.12 Capture pilot evidence needed for learning and future authority changes without self-modification.


3. Non-Functional / Governance Requirements
High observability; reviewer actions auditable; control plane independent enough to disable faulty vertical slices; logs must avoid secrets/PII where unnecessary; test environments isolated from production accounts; deterministic feature gating; backup/recovery expectations documented; no control mechanism may silently assume domain authority.

7. Prompt / Model / Tool Responsibilities
Models may summarize trace/evidence and assist reviewers, triage failures or draft incident summaries. They may not approve themselves, alter feature gates, grant permissions, suppress failed tests or autonomously change canonical truth/authority.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
Owner/operator console: review queue, pending material decisions, trace/evidence viewer, package/feature gates, incidents, Meta validation status, privacy requests, multi-business isolation warnings, QA runs and pilot health. User-facing surfaces show review/pending/blocked states only when relevant.


9. Authority / Consent / Human Review Gates
Human Review is mandatory for material pilot decision classes. Review does not move domain ownership. Feature gates/kill switches can prevent execution but cannot create professional decisions. Owner retains authority to open/close Build/Runtime waves explicitly.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Reviewers receive minimum-sufficient governed evidence/decision/authority package and necessary domain context, not private chain-of-thought or unrestricted whole-user data.


11. Evidence / Event / Readback Requirements
Every review, gate change, incident, permission change, material test, live validation, kill/hold action and recovery is auditable and linked to affected package/requirement/trace. Pilot evidence separates system behavior from professional/business outcomes.


12. Metrics / Measurement Requirements
Review coverage/latency, blocked unauthorized actions, trace completeness, isolation violations, incidents by package, recovery success, test pass/fail, feature-gate interventions, privacy/security issues, Meta read/write validation status. No vanity health score should hide failed critical gates.


13. Failure / Recovery / Rollback / Semantic Return
Control plane failure defaults to blocking material write actions; reviewer unavailable→pending/blocked rather than auto-approve; logging failure on a critical/material external write is governed by the owner-approved fail-closed audit contract in section 21: durable pre-write governance evidence is mandatory; possible post-write persistence failure yields UNKNOWN / RECOVERY_REQUIRED, never ordinary success; incident can disable package; recovery must preserve evidence.


14. Security / Privacy / Multi-Business Isolation
Role-based/least-privilege access; strong separation of test/live credentials; secret management; audit log protections; multi-business/tenant isolation; PII minimization; retention/deletion hooks; secure exports; dependency/security scanning expectations before pilot; privacy/legal sign-off gates where required.


15. Tests
Golden E2E both branches; unauthorized write blocked; reviewer self-approval prohibited; feature kill switch stops targeted package; multi-business leakage tests; stale/partial Meta cases; retry/idempotency incidents; Semantic Return edge cases; privacy deletion/retention hook tests; operator recovery drill.


16. Acceptance Criteria
AC-12.1 100% material pilot decisions are review-gated.
AC-12.2 Every material action/result has a reconstructable trace.
AC-12.3 Package/feature kill switches can stop unsafe paths without corrupting unrelated state.
AC-12.4 Multi-business isolation has passing negative tests.
AC-12.5 Unauthorized/stale/partial execution scenarios fail safely.
AC-12.6 Critical privacy/security/QA gates are visible and auditable.
AC-12.7 No pilot package can silently bypass this overlay.


17. Migration / Compatibility
Existing logs/review records may be imported as historical evidence where trustworthy; old operator/admin controls require mapping to new gates/roles; legacy unreviewed material actions remain historical and do not create precedent.


18. Deferred / Open Decisions
Final IAM provider/role model, observability stack, SIEM/security tooling, retention periods, incident severity matrix, legal/privacy policy details, production SLOs, automated risk tiers after pilot validation.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.


19. Traceability
Constitution/Product Truth governance + BP-00 + Human Review pilot doctrine + Roadmap Phases 7–8 → all Stage/Contract material gates → BP-12 controls/tests.
Every implemented requirement must map back to approved Truth/Core/Flow/Stage/Contract and forward to a test/evidence requirement.

21. OWNER-APPROVED EXTERNAL-REVIEW REMEDIATION — PILOT CONTROL CONTRACT
21.1 Canonical review persistence. BP-12 owns ReviewQueueItem/control-plane lifecycle only. Resolution of a queue item must create or reference the same canonical BP-00 HumanReviewRecord identity; review_record is an implementation projection, not separate review truth.
21.2 Pilot Material Decision Registry. Mandatory registry families: STRATEGY; CREATIVE_CLAIM_OR_MEANING; BRAND_TRUTH_CHANGE; MEDIA_BUDGET; LAUNCH_LIVE_WRITE; RECOVERY_ROLLBACK; BUSINESS_INTERVENTION; MEASUREMENT_CAUSAL_INTERPRETATION; LEARNING_PROMOTION_REUSE; CLOSURE_EXTENSION. Each class maps to a qualified human reviewer aligned with the owning professional or operational domain. Cross-domain material decisions require coverage of each materially affected ownership boundary or an explicitly approved combined reviewer qualification. Automation/model self-review is forbidden.
21.3 Fail-closed classification. Any decision/action that reaches a material professional/execution boundary without a recognized registry class is REVIEW REQUIRED / BLOCKED. Unclassified never defaults to non-material.
21.4 Review proof. A material decision cannot advance past its review gate unless a canonical HumanReviewRecord exists for the exact subject/version/decision class and carries an allowed review outcome from the required qualified human reviewer.
21.5 Critical audit precondition. Before any material external write, durable governance evidence must already persist: scoped intent, exact subject/version, valid authority identity, required HumanReviewRecord, protected constraints and pre-issued operation identity. Failure to durably persist these items blocks execution.
21.6 Post-write audit uncertainty. If provider action may have occurred but post-write audit/evidence persistence fails, the operation state is UNKNOWN / RECOVERY_REQUIRED. It must not be represented as success or verified. Recovery must use the pre-issued operation identity, idempotency protection and authoritative readback.
21.7 Epistemic states. BP-12 control surfaces and traces preserve UNKNOWN, MISSING, UNVERIFIED and NOT_APPLICABLE as distinct states per BP-00 v1.1; no generic fail/null coercion is permitted.
21.8 Mandatory tests. For each registry family, a material decision without Human Review is blocked; UNCLASSIFIED is blocked; reviewer self-approval by model/automation is blocked; resolved queue references canonical HumanReviewRecord; pre-write durable-evidence failure blocks external write; simulated provider-success plus post-write logging failure yields UNKNOWN/RECOVERY_REQUIRED; trace reconstruction links scope→decision→review→authority→operation identity.
21.9 Acceptance additions. AC-12.8 Materiality classification is deterministic enough to prove registry coverage; unclassified fails closed. AC-12.9 BP-12 review lifecycle has no parallel review truth. AC-12.10 Every material external write has durable pre-write governance evidence and operation identity. AC-12.11 Post-write audit uncertainty never becomes normal or verified success.
