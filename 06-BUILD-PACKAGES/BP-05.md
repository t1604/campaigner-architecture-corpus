One-Time Intake / Brief / Commercial Journey

0. Purpose and Build Boundary
Implement the one-time campaign path from direct entry through campaign-specific intake, professional brief/recommendation and explicit service scope/price/payment, without forcing the ongoing business diagnosis or Full Strategy.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: B1, B2, B3.
Contracts: C03, C04; produces the campaign truth consumed by C07.
Primary domain/core ownership: Advisor primary; Context/Knowledge/Experience required; Director/Media/Meta/Metrics/Golden Lead conditional; Billing downstream only.
Dependencies: BP-00, BP-01, BP-02.


2. Functional Requirements
FR-05.1 Collect only campaign-specific truth: what is advertised, purpose/objective, audience, geography, time/event date/window, total media budget and limits, offer/price/terms, CTA/destination, optional assets, constraints and End Condition.
FR-05.2 Support events/products/properties/jobs/offers and other bounded one-time objects without requiring a generic business diagnosis.
FR-05.3 Determine Minimum Sufficient Campaign Understanding and ask targeted follow-ups only when they can change the campaign recommendation.
FR-05.4 Create One-Time Campaign Brief with assumptions/Unknowns and Advisor Recommendation.
FR-05.5 Recommendation may define several managed phases over weeks/months while remaining one One-Time campaign.
FR-05.6 Allow optional asset upload before/within Studio handoff.
FR-05.7 Present service scope and price separately from Media Budget and other production/provider costs.
FR-05.8 Confirm payment/entitlement before paid Studio/production work where required.
FR-05.9 Carry End Condition explicitly downstream.
FR-05.10 Offer conversion to ongoing branch only by explicit user choice if the request is substantively ongoing.


3. Non-Functional / Governance Requirements
Fast path must remain professional rather than shallow; intake must support resume/edit; date/time and budget handling must be timezone/currency-safe; commercial/payment state idempotent; no diagnosis-state contamination from ongoing branch.


4. Conceptual Data Objects and Relationships
OneTimeCampaign; CampaignObjective; AudienceIntent; GeoIntent; TimeWindow; BudgetEnvelope; Offer/CTA/Destination; AssetSubmission; EndCondition; OneTimeBrief; OneTimeRecommendation; OneTimeServiceScope; PaymentEntitlement.

6. API / Integration Requirements
startOneTimeCampaign; updateIntake; addAsset; evaluateCampaignSufficiency; generateOneTimeBrief; presentRecommendation; selectOneTimeScope; create/confirmPayment; handoffOneTimeBriefToStudio.


7. Prompt / Model / Tool Responsibilities
Advisor model may ask targeted campaign questions and recommend a campaign plan, audience/geo intent, timing and budget framing using professional knowledge. It may not force ongoing strategy or pretend platform mechanics are user responsibilities.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
Direct One-Time journey with concise progressive sections: what/why; audience/where; when; budget; offer/CTA/destination; assets; review Brief; scope/price/payment. Allow user to skip assets. Show defined End Condition clearly.


9. Authority / Consent / Human Review Gates
Intake/recommendation/payment confer no launch authority. Payment is service entitlement only. Material recommendation receives Human Review in pilot.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Campaign-scoped local truth only; reuse existing business/brand context only when relevant and explicitly scoped. Knowledge activation limited to the specific campaign decision.


11. Evidence / Event / Readback Requirements
Record user-provided campaign facts/source, brief versions, assumptions/Unknowns, recommendation rationale, asset submissions, End Condition, service-scope choice and payment state.


12. Metrics / Measurement Requirements
Operational: intake completion, missing material facts, brief reopen reasons, asset availability, payment errors, end-condition completeness. No success claim before downstream measurement.


13. Failure / Recovery / Rollback / Semantic Return
Missing facts→targeted question; insufficient budget/time→responsible scope alternative; event/date change→reopen B1/B2; payment failure preserves brief; scope mismatch returns to Advisor; no automatic branch switch.


14. Security / Privacy / Multi-Business Isolation
Uploaded assets scoped to user/business/campaign; user-supplied rights status preserved; payment handled via provider; no automatic reuse across businesses.


15. Tests
One-Time path never initializes A1/A4/A5; required campaign facts handled progressively; optional asset path works with no upload; date/End Condition persisted; multi-phase recommendation remains one campaign; service price/media budget separated; payment gives no authorization.


16. Acceptance Criteria
AC-05.1 User can define and purchase a one-time advertising service without ongoing diagnosis.
AC-05.2 Brief contains objective, audience/geo, time, budget, offer/CTA/destination, constraints, assets state and End Condition as relevant.
AC-05.3 Assets are optional.
AC-05.4 Long managed duration does not convert campaign to ongoing flow automatically.
AC-05.5 Service price and Media Budget are separate.
AC-05.6 Paid campaign truth is ready for B4 Studio handoff.


17. Migration / Compatibility
Replace historical 'quick diagnosis→simple campaign' one-time mechanics while preserving D-062 lineage; migrate any existing one-time records only if their scope/end-state can be identified.


18. Deferred / Open Decisions

Deferred items are not silently treated as defaults. Any blocker status must be explicit.

21. OWNER-APPROVED EXTERNAL-REVIEW REMEDIATION — ONE-TIME SCOPE
21.1 All BP-05 material objects resolve through BP-00 v1.1 canonical ScopeRef. The draft business_id? field is not an ownership primitive and must not be used as one.
21.2 A One-Time Campaign may validly exist without a Business. In that case its canonical scope is an explicit user-owned ONE_TIME_CAMPAIGN scope with its own campaign identity and lineage.
21.3 If an existing Business is relevant and explicitly attached, the relationship is recorded without changing the One-Time Campaign identity. Later attachment to a Business is an explicit governed relationship; it never occurs by inference, never rewrites prior provenance, and never creates cross-business inheritance.
21.4 Assets, Brief, PaymentEntitlement, EndCondition and downstream handoffs must carry the same canonical ScopeRef or an explicit allowed child/reference relation. Missing/ambiguous scope fails closed and returns for scope resolution.
21.5 Tests: create One-Time campaign without Business; upload/submit campaign-scoped asset without Business leakage; explicitly attach later to Business while preserving campaign lineage; attempt implicit attachment and block; attempt cross-business reuse and block; serialization of absent Business does not convert scope to UNKNOWN Business or default Business.
21.6 Acceptance additions. AC-05.7 Every material One-Time object has a canonical ScopeRef even when Business is absent. AC-05.8 Business attachment is explicit, auditable and non-reparenting. AC-05.9 No One-Time scope operation can infer or inherit another Business.


22. OWNER-APPROVED ENTITLEMENT LIFECYCLE — F1 REMEDIATION
22.1 BP-05 consumes C04 v1.1 and BP-03 v1.1 entitlement semantics. One-Time PaymentEntitlement remains scoped to the canonical One-Time ScopeRef and never creates Approval, Authorization, Execution or Launch authority.
22.2 Cancellation/refund/chargeback do not erase the One-Time Campaign, Brief, EndCondition, Asset history, completed professional work, Human Review, Authority or Lineage.
22.3 A governed entitlement-state change may suspend or terminate future paid Studio/production/professional work not yet performed. If material work is already in progress, no new material stage, irreversible production cost or new external commitment may begin until Human/Commercial Review resolves entitlement.
22.4 Chargeback/payment dispute changes only entitlement to continue professional work. It cannot re-parent the campaign, infer a Business, revoke historical review/authority, or change execution history.
22.5 Every entitlement transition is auditable, scope-bound and version-bound and records the triggering commercial event/source. Duplicate callbacks are idempotent.
22.6 Exact monetary refund formula, fees, legal terms and provider-specific dispute mechanics remain Deferred; Build must not invent them.
22.7 Tests: One-Time cancellation preserves campaign/brief/end-condition lineage; future paid work is suspended/terminated by governed entitlement state; in-progress material work blocks new irreversible commitment pending review; chargeback cannot change ScopeRef or Authority/Review history; duplicate callbacks are idempotent.
22.8 Acceptance additions. AC-05.10 Entitlement lifecycle preserves One-Time identity and history. AC-05.11 Entitlement change cannot create or rewrite live-action authority. AC-05.12 Ambiguous/in-progress entitlement state fails closed for new material paid work pending Human/Commercial Review.


23. OWNER-APPROVED ONE-TIME MEDIA FUNDING / UNUSED BALANCE SEMANTICS
Owner Decision source: CAMPAINER-ONE-TIME-UNUSED-MEDIA-BALANCE-OWNER-DECISION-001 — APPROVED / LEGAL-FINANCE RELEASE GATE — ID 1-kiC1QKNgeqwpuKdfC_cto8J1JwFz-wAAaYqNKiJF7Q.
Related hard invariant: CAMPAINER-MEDIA-FUNDING-NO-CREDIT-EXPOSURE-OWNER-DECISION-001 — ID 1VMKuxBFX7nJNG5_wh7-cRyE_irEojEEAr8tCu5V4HVY.


23.1 One-Time commercial intake must represent Service Entitlement and Media Funding as separate governed balances/states. Paying for service does not fund Meta; media funding does not itself create service entitlement, professional approval or launch authority.
23.2 One-Time media funding is scope-bound to the exact user/ONE_TIME_CAMPAIGN ScopeRef and carries source-payment identity/version/status. Pending/unsettled/disputed funding is not safe spendable coverage.
23.3 The purchase/confirmation UI must disclose the separation between service price and media funding and preserve the future unused-balance disposition path without promising automatic refund or forfeiture.
23.4 If a One-Time campaign later closes early by user instruction, any eligible unused media remainder is governed by C14 v1.2/BP-11 v1.2: after verified closure and protected Meta coverage floor it becomes a segregated user-identified balance, not Campainer revenue.
23.5 Funding Balance ≠ Spending Authorization. Existing residual funding cannot silently enlarge a future campaign budget or initialize another campaign.
23.6 User-requested return of eligible residual funding is a distinct media-balance refund path, not a reversal of completed professional work/service entitlement history.
23.7 Release of unclaimed residual balance to Campainer after a safety/claim period is NOT implementable from F1 alone and remains blocked behind the Legal/Finance gate defined by the Owner Decision. F1 must not invent the waiting period, forfeiture/right-to-release terms or accounting treatment.
23.8 Tests: service-payment success cannot mint media funding; media-funding success cannot mint launch authority; disputed funding is not spendable; exact One-Time scope binding; residual balance cannot be auto-consumed by a later campaign; F1 cannot mark residual media balance as Campainer revenue.
23.9 Acceptance additions. AC-05.13 One-Time service entitlement and media funding remain separate. AC-05.14 Media funding is exact-scope, pre-funded and cannot become post-paid Campainer credit exposure. AC-05.15 F1 preserves but does not execute the later unused-balance release-to-Campainer rule while its Legal/Finance gate is open.
