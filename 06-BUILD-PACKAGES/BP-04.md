CAMPAINER-BUILD-PACKAGE-BP-04-001 — v1.0
Business/Ongoing Deep Understanding & Full Strategy
STATUS: OWNER-APPROVED BUILD REQUIREMENTS
BUILD AUTHORITY: NO
RUNTIME AUTHORITY: NO
META WRITE / LAUNCH AUTHORITY: NO
PRODUCT OWNER AUTHORITY: PRESERVED
DERIVES FROM: CAMPAINER-BUILD-PACKAGES-MASTER-001 v1.0 + applicable Canonical Flow / Stage Truth / Contracts / Domain Cores.


0. Purpose and Build Boundary
Implement progressive deep understanding, a scoped Baseline and Full Strategy so strategy is grounded in local truth, professional knowledge, measurement meaning and explicit Unknowns rather than a fixed questionnaire or platform-led tactic.
This package is a requirements artifact. It may propose concrete schemas/interfaces only as DRAFT implementation candidates. It does not authorize coding, deployment, runtime writes or Meta writes.


1. Canonical Coverage
Stages: A4, A5.
Contracts: C05; downstream input to C06.
Primary domain/core ownership: Advisor primary; Director frames; Context, Knowledge/Evidence, Metrics and Golden Lead required/conditional as Stage Truth specifies.
Dependencies: BP-00, BP-01, BP-03.


2. Functional Requirements
FR-04.1 Reopen diagnosis progressively by Decision Need; no fixed deep-question count.
FR-04.2 Represent Business, Offering, Customer/Account, Buyer State, Buying Situation, Journey, economics, capacity, sales handling, Brand/Proof and constraints as optional scoped truth.
FR-04.3 Capture Baseline Snapshot, measurement availability and concurrent changes before material intervention.
FR-04.4 Stop asking when remaining Unknowns no longer materially affect Strategy/Audience/Offer/Creative/Executability/Risk/Measurement.
FR-04.5 Frame Current State→Desired State→Problem/Bottleneck/Opportunity before Strategy.
FR-04.6 Compare candidate mechanisms/strategies with evidence for/against, tradeoffs and Unknowns.
FR-04.7 Produce Strategic Intent including Strategic Job, buyer-state change, Must-Believe, Proof Requirement, Offer/Route/Next Step and Measurement Intent.
FR-04.8 Support user correction/choice/approval without converting approval to live authority.
FR-04.9 Return to A4/domain owner when understanding or feasibility cannot support the strategy.


3. Non-Functional / Governance Requirements
All strategy claims must be reconstructable from governed Context/Knowledge; Baseline must distinguish stated/measured/unknown; platform capability cannot select Strategy; decision artifacts versioned; material strategy receives Human Review in pilot.


4. Conceptual Data Objects and Relationships
DeepUnderstanding; BaselineSnapshot; MarketingProblem; StrategyCandidate; StrategicIntent; MustBelieve; ProofRequirement; MeasurementIntent; ConcurrentChangeRef.


5. Proposed Concrete Schemas — DRAFT / NOT APPROVED

DRAFT.
Schema rule: IDs, fields, enums, indexes and persistence mechanics remain DRAFT until separately approved. No inferred field is canonical merely because it appears here.


6. API / Integration Requirements
openTargetedDiagnosis; updateDeepUnderstanding; createBaselineSnapshot; create/compareStrategyCandidates; submitStrategyRecommendation; recordStrategyChoice/Approval; handoffStrategicIntentToStudio.


7. Prompt / Model / Tool Responsibilities
Advisor/Director models may synthesize strategy from governed projections, generate candidate mechanisms and explain recommendation. They may not start from Meta convenience, hide contradictory evidence or assert causal certainty beyond Metrics semantics.
Prohibited: private chain-of-thought storage; silent authority expansion; turning Prior into Local Truth; silent strategy/brand/budget/measurement changes outside the owning Core.


8. UI / Workbench Requirements
Progressive diagnostic workbench; Baseline state; professional strategy view showing problem, evidence, unknowns, recommendation and what would change it; user correction/approval; no questionnaire-count framing.


9. Authority / Consent / Human Review Gates
Strategy approval is distinct from execution authorization. Human Review required for material strategy recommendation/approval in pilot.
Pilot default: 100% Human Review for material professional/execution decisions covered by this package.


10. Context / Knowledge Projection Interfaces
Minimum-sufficient local business/buyer/economic/sales/brand/measurement context plus scoped strategy/domain knowledge; only relevant Meta possibility/constraints when decision-relevant.


11. Evidence / Event / Readback Requirements
Baseline version/source/maturity; local claim/correction lineage; candidate strategy evidence for/against; selected Strategic Intent; assumptions/Unknowns; user decision/review.


12. Metrics / Measurement Requirements
Baseline completeness/missingness, question decision-value, strategy reopen causes and measurement-readiness gaps. Business outcomes remain downstream; no strategy-quality score without validation.


13. Failure / Recovery / Rollback / Semantic Return
Insufficient understanding→targeted question/Return; unclear measurement meaning→Metrics Return; specialist constraint that changes meaning→Advisor/Director reopen; no fake completion.


14. Security / Privacy / Multi-Business Isolation
Business-scoped Context only; sensitive economics/sales data need-to-know; cross-business patterns enter as Knowledge/Prior, never local truth.


15. Tests
No fixed question count; Baseline preserves unknown/missing; platform-only tactic cannot pass as strategy; contradiction causes appropriate reopen; Strategic Intent has required semantic content; approval produces no authorization.


16. Acceptance Criteria
AC-04.1 Full Strategy is traceable to A4 Context/Knowledge/Baseline.
AC-04.2 Problem/Bottleneck precedes material strategy.
AC-04.3 Unknowns can remain without false completion.
AC-04.4 Strategic Intent is sufficient for Studio without Studio inventing strategy.
AC-04.5 Strategy approval and live authority remain separate.


17. Migration / Compatibility
Legacy deep questionnaire answers become historical local evidence where provenance exists; old strategy drafts remain lineage, not active truth.


18. Deferred / Open Decisions
Exact strategy taxonomy, Buyer State schema, Baseline field set, Golden Lead score/formula, experiment designs, calibration thresholds.
Deferred items are not silently treated as defaults. Any blocker status must be explicit.


19. Traceability
Product Truth + Director/Context/Metrics/Golden Lead Cores → Stage Truth A4/A5 → C05 → BP-04.
Every implemented requirement must map back to approved Truth/Core/Flow/Stage/Contract and forward to a test/evidence requirement.


20. Build Authority Gate
This package remains NON-EXECUTABLE until the Product Owner explicitly grants Build Authority to this package or to a governed release wave that names it.
