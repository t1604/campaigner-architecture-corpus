CAMPAINER-CANONICAL-PRODUCT-FLOW-001 — v1.0
ה־Flow הקנוני של Campainer


STATUS: OWNER-APPROVED CANONICAL PRODUCT FLOW — PRINCIPLE / FLOW
ACTIVE CANONICAL FLOW: YES
SCHEMA AUTHORITY: NO
BUILD AUTHORITY: NO
RUNTIME AUTHORITY: NO
META WRITE / LAUNCH AUTHORITY: NO
PRODUCT OWNER AUTHORITY: PRESERVED


0. מעמד וסמכות המסמך
מסמך זה מקבע את ה־Canonical Product Flow של Campainer ברמת Principle / Flow. הוא נגזר מחוקת Campainer, Product Truth Core, 13 ליבות התחום הפעילות, Final Core Architecture, ההכרעות על Strategy Initial, והמסלול החד־פעמי שאושר בנפרד.


המסמך קובע את מסע המוצר, גבולות ה־Stages, מטרותיהם, בעלי האחריות, Handoffs, Authority Gates, Evidence Writes, Exit ו־Reopen ברמת העיקרון. הוא אינו קובע Screens, Navigation, Schema, API, DB, Enums, Thresholds, Pricing Formula, Prompt, Model Vendor או Runtime implementation.


Stage במסמך זה אינו בהכרח מסך. כמה Stages יכולים להיות מוצגים באותו Workspace, ו־Stage אחד יכול לכלול כמה Moments/Interactions. שינוי UI אינו משנה Flow Truth כל עוד המשמעות, הבעלות והגבולות נשמרים.


1. תזת ה־Flow
Campainer היא מערכת מקצועית אחת ורציפה. המשתמש פוגש Advisor אחד, בעוד מאחוריו פועלות ליבות מקצועיות שונות.


ה־Flow אינו Pipeline חד־פעמי שמסתיים ב־Launch. הוא מעגל:
UNDERSTAND
→ CREATE INSIGHT
→ RECOMMEND
→ EXPLAIN
→ ENABLE CHOICE
→ EXECUTE WITH AUTHORITY
→ MEASURE
→ LEARN
→ IMPROVE THE NEXT DECISION.


ה־Flow חייב לשמור:
Professional Decision before Technical Execution.
General Knowledge → Hypothesis/Question → Local Evidence → Local Understanding.
Recommendation ≠ Permission.
Payment ≠ Approval ≠ Authorization ≠ Execution.
Capability ≠ Authority.
Result ≠ Causal Explanation.
Learning Candidate ≠ Truth.
Unknown ≠ Zero/Fail.
No Shadow Decision.
No False Dead End.
Minimum-Sufficient Projection.
Semantic Return.
One continuous Advisor.


2. ארכיטקטורת הכניסה — שני ענפים רשמיים
בנקודה שבה מתחיל האבחון הקצר קיימות שתי כניסות מוצריות ברורות.


A. המסלול העסקי / המתמשך
המשתמש נכנס לאבחון הקצר ומתחיל את המסע המקצועי המתמשך של Campainer.


B. המסלול החד־פעמי
כפתור/בחירה נפרדים וברורים: “אני רוצה לפרסם משהו חד־פעמי”.
הבחירה מנתבת ישירות ל־CAMPAINER-ONE-TIME-CAMPAIGN-FLOW-001.
אין חובה להתחיל או להשלים את האבחון העסקי הקצר.
המסלול החד־פעמי אינו תוצאה של Route Recommendation במסלול העסקי.
אין מסך כללי המחייב בחירת מסלול לפני שתי הכניסות.


שני הענפים שייכים לאותו Campainer ולאותו Advisor. הם שונים בעומק ההבנה ובסוג המשימה, לא בזהות המוצר.


3. חוזים רוחביים החלים בכל Stage
3.1 Context Projection
כל Stage מקבל רק את האמת המקומית הדרושה להחלטה הנוכחית. Complete User Context נשאר Source of Local Truth ואינו מועתק ל־Stage כ־State מקביל.


3.2 Knowledge Projection
ידע מקצועי מופעל לפי Decision Need, Domain, Scope, Status ו־Freshness. אין טעינה עיוורת של כל הקורפוס.


3.3 Semantic Handoff
כל Handoff מהותי חייב לשמר מספיק משמעות כדי שהמקבל יוכל לפעול מקצועית בלי לנחש: Scope, Intent, relevant Local Truth, Evidence/Lineage, Unknowns, Freshness, Authority state, Constraints, professional freedom ו־Return Conditions.


3.4 Semantic Return
כאשר המקבל אינו יכול לשמור על המשמעות, הסמכות, ה־Scope, הראיות או האילוצים — הוא מחזיר את הבעיה לבעל ההחלטה המתאים. Return הוא תוצאה מקצועית לגיטימית.


3.5 No Shadow Decision
אף Core, Specialist, Platform או Executor אינו רשאי לשנות בשקט Strategy, Budget Intent, Brand Truth, Claim, Audience Meaning, Measurement Target, User Authority או Execution Semantics מחוץ לתחומו.


3.6 Authority
ההבחנה נשמרת:
Professional Recommendation
→ User Choice / Decision
→ Approval, כאשר נדרש
→ Authorization
→ Execution
→ Verified Readback.
Payment הוא תנאי מסחרי נפרד ואינו יוצר Authority טכני.


3.7 Evidence / Traceability
להחלטות ופעולות מהותיות צריך להיות Lineage מספיק:
Purpose / Goal
→ Applicable Truth / Knowledge
→ Local Context / Evidence
→ Decision / Recommendation
→ Choice / Approval / Authorization
→ Execution
→ Readback
→ Measurement
→ Learning / Next Decision.


3.8 Reopen
כאשר המציאות משתנה, חוזרים ל־Stage המקצועי הנכון — לא בהכרח להתחלה.


4. ענף A — המסלול העסקי / המתמשך


4.1 Stage 1 — אבחון קצר / Minimum Sufficient Initial Understanding
Purpose:
להבין מספיק את העסק והצורך כדי לייצר Insight ו־Strategy Initial אחראיים, בלי לדרוש הבנה מלאה של העסק.


Decision / Understanding Target:
מי המשתמש וה־Business הפעיל; מה ה־Offering הרלוונטי; מה המשתמש רוצה להשיג; מהו המצב הקיים; מי הלקוח/העבודה הרצויים ברמה ראשונית; אילו מגבלות ו־Unknowns מהותיים קיימים.


Primary professional ownership:
Advisor — שיחה, הבנה והצגה.
Director — Decision Need / depth framing.
Context — Local Truth.
Knowledge — Priors/Questions/Evidence.


User-facing interaction:
אבחון קצר, דינמי ומוסבר. שואלים רק מידע שיכול לשנות את Strategy Initial או את מידת האחריות שבה ניתן לתת אותה.


Context Projection:
Business/Offering/Goal/known state/relevant history בלבד.


Knowledge Need:
Industry/strategy/customer/business priors הדרושים ליצירת Hypotheses ושאלות טובות יותר. Prior אינו Local Fact.


Output:
Minimum Sufficient Initial Understanding + explicit Unknowns + basis ל־Strategy Initial.


Authority:
אין Execution Authority. מידע שהמשתמש מוסר נשמר בהתאם ל־Scope/Source/Confidence.


Evidence writes:
Local claims, source, scope, corrections, material Unknowns.


Exit:
יש מספיק הבנה כדי לייצר Strategy Initial אמיתית ושימושית.


Reopen:
מידע חדש שמשנה מהותית את ההבנה הראשונית. אין “חזרה לשאלון”; נשאלת שאלה ממוקדת לפי Decision Need.


4.2 Stage 2 — Strategy Initial + Route Recommendation
Purpose:
לתת ערך מקצועי אמיתי לפני תשלום ולהציג את הכיוון הראשוני של Campainer.


כלל קנוני:
Route Recommendation אינה Stage נפרדת. היא פרק הסיום והמסקנה של Strategy Initial.


Strategy Initial צריכה להיות תוצר קוהרנטי שמסוגל לשאת:
מה הבנו;
מה אנחנו רואים;
הבעיה/ההזדמנות הראשונית;
שלוש תובנות מקצועיות כחלק מהתוצר, לא כ־Stage נפרד;
מה מומלץ לעשות;
הנחות/Unknowns;
מה ייבדק לעומק לאחר תשלום;
ומסקנת Route Recommendation — איזו מעטפת ביצוע מתאימה ולמה.


Decision Target:
האם קיימת תמונה מקצועית ראשונית מספקת, ומהו המסלול העסקי המומלץ לביצועה.


Primary ownership:
Advisor — synthesis, recommendation, explanation.
Director — bounded decision frame.
Knowledge/Context/Golden Lead — inputs לפי צורך.


User-facing interaction:
המשתמש רואה קודם את ההיגיון והערך ורק בסוף את המלצת המסלול. אין לחץ מכירתי בין Insight להמלצה.


Output:
Strategy Initial + route recommendation + rationale + roadmap + conditions for reconsideration.


Authority:
Recommendation אינה Permission ואינה Execution Authorization.


Evidence writes:
Strategy Initial version, evidence basis, assumptions, unknowns, recommendation state.


Exit:
המשתמש מבין מה Campainer הבינה, מה היא ממליצה, למה ואיזה מסלול נדרש.


Reopen:
שינוי מהותי ב־Business/Offering/Goal או מידע שסותר את הבסיס הראשוני.


4.3 Stage 3 — בחירה, Service Scope ותשלום
Purpose:
לאפשר למשתמש לבחור ולהתקשר מסחרית לאחר שכבר קיבל ערך והבין את ההמלצה.


User-facing minimum:
המסלול/Scope שנבחר;
מה השירות כולל;
מחיר Campainer;
Media Budget בנפרד;
עלויות AI/Production/Provider מהותיות אם קיימות;
ומה אינו כלול.


Financial boundary:
Campainer Service Price ≠ Media Budget ≠ other approved cost layers.


Authority boundary:
Payment ≠ Strategy Approval ≠ Creative Approval ≠ Execution Authorization ≠ Launch.


Primary ownership:
Advisor/Experience — הסבר ובחירה.
Commercial/Billing downstream contract — תשלום.
Context — שמירת choice/payment status ברמת האמת המקומית המתאימה.


Exit:
Scope understood + payment confirmed כאשר נדרש.


Reopen:
שינוי מסחרי מהותי ב־Scope, משך או עלויות.


4.4 Stage 4 — אבחון מעמיק פרוגרסיבי + Baseline
Purpose:
להעמיק רק במידע שנדרש כדי לקבל Full Strategy אחראית ומדידה, ולשמור נקודת התחלה שתאפשר להבין מה השתנה בהמשך.


Decision / Understanding Target:
Business, Offering, Customer/Account, Buyer State, Buying Situation, Journey, Marketing Problem/Bottleneck, Golden Lead, Economics, Capacity, Sales/Lead Handling, Brand, Proof, Measurement ו־Constraints — לפי הרלוונטיות בלבד.


Progressive Diagnosis:
אין מספר שאלות קבוע. שואלים כאשר התשובה יכולה לשנות Strategy, Audience, Offer, Creative, Executability, Risk או Measurement. עוצרים כשמגיעים ל־Minimum Sufficient Understanding להחלטה.


Baseline:
לפני Intervention מהותי נשמר Scoped Baseline של הממדים הרלוונטיים, כולל מה נמדד, מה user-stated, מה Unknown ומהם concurrent changes מהותיים.


Primary ownership:
Advisor — ההבנה והשיח.
Context — local state/history/baseline facts.
Director — depth/decision framing.
Metrics — measurement meaning.
Knowledge — relevant professional knowledge.


Evidence writes:
Local facts/claims, baseline state, material unknowns, source/lineage, planned concurrent changes.


Exit:
יש מספיק אמת מקומית ו־Measurement meaning כדי לקבל Full Strategy אחראית.


Reopen:
New Evidence, contradiction, business change, outcome maturation או Decision Need חדש.


4.5 Stage 5 — Full Strategy
Purpose:
לסגור את ההחלטה המקצועית המרכזית שממנה ייגזרו Studio, Media, Execution ו־Measurement.


Professional chain:
Current State
→ Desired State
→ Marketing Problem / Bottleneck / Opportunity
→ Buyer / Buying Situation
→ Candidate Mechanisms
→ Candidate Strategies
→ Evidence For / Against
→ Unknowns / Breakers
→ Tradeoffs
→ Recommended Strategy
→ Strategic Job / Desired Buyer-State Change
→ Must-Believe / Proof Requirement
→ Offer / Route / Next Step
→ Measurement Intent.


Primary ownership:
Director — Decision Frame.
Advisor — professional judgment, recommendation and explanation.
Applicable domains — professional inputs.


User-facing interaction:
Advisor מציג עמדה מקצועית אמיתית, הנחות, סיכונים ומה ישנה את ההמלצה. המשתמש יכול לתקן Local Truth ולבחור/לאשר כאשר נדרש.


Authority:
Strategy Approval אינה External Write Authorization.


Output:
Approved/selected Strategic Intent + downstream semantic basis.


Evidence writes:
Decision lineage, evidence/unknowns, strategy version, user choice/approval where applicable.


Exit:
Strategic Intent מספיק סגור להעברה ל־Studio ול־Campaign Readiness.


Reopen:
שינוי Goal, Bottleneck, Offering, Buyer State, constraint, major evidence או failure שמחייב שינוי משמעות.


4.6 Stage 6 — Studio
Purpose:
להפוך Strategic Intent לנכסים ולקמפיין מוכן מקצועית תוך הפרדה בין Brand Truth לבין Creative Judgment.


Studio הוא מקום מוצרי אחד עם שני חדרים מקצועיים.


חדר נכסי המותג — Brand / Brand Assets:
מחזיק Brand Truth, Source/Master lineage, Assets, Proof Assets, Rights, Consent, Provenance, Readiness, Restrictions ו־Missing Assets.
הוא מייצר Minimum-Sufficient Brand Snapshot לשימוש הנוכחי.
Missing ordinary asset אינו Automatic Stop.


חדר יצירת הקריאייטיב — Creative:
מקבל Strategic Intent, Buyer State, Creative Job, Must-Believe, Proof Requirement, Offer/CTA, Brand Snapshot, assets, platform constraints ו־measurement intent.
הוא מחליט Representation → Concept → Execution → meaningful variants.


Internal flow:
Brand Assets ↔ Creative לפי צורך.
Creative יכול Semantic Return לחדר הנכסים/Advisor כאשר חסר Proof/Asset או כאשר הפתרון דורש שינוי Brand/Strategy מהותי.


Primary ownership:
Brand Core — brand truth/assets/readiness/rights.
Creative Core — representation/concept/execution judgment.
Advisor/Director — strategic meaning.


Authority:
Creative freedom קיימת בתוך constraints מאושרים. שינוי משמעות אסטרטגית או protected Brand Truth דורש Return/approval מתאים.


Output:
Campaign Creative Package + relevant asset lineage + unresolved material gaps.


Exit:
יש תוצרים מספיקים ל־Campaign / Execution Readiness.


Reopen:
Asset/rights change, proof gap, strategy change, campaign learning או Creative-specific issue.


4.7 Stage 7 — Campaign / Execution Readiness
Purpose:
לחבר Strategy + Studio + Media/Budget + Meta + Measurement + Business Realization + Authority readiness למהלך שניתן לבצע באחריות.


Media/Budget contribution:
allocation, pacing, add/hold/reduce/reallocate/test/wait/preserve לפי marginal opportunity, economics, capacity, realization, uncertainty ו־risk — לא לפי KPI ממוצע בלבד.


Meta contribution:
current possibility, capability, constraints, permissions, enablement state, signal transport ו־freshness. Meta אינו בוחר Strategy או Budget.


Measurement contribution:
הגדרת outcome/metric semantics, baseline, lineage, signal/business readiness, maturity ו־prohibited inference.


Sales/Business realization contribution:
יכולת להבין response/contact/qualification/opportunity/outcome כאשר רלוונטי, בלי להפוך realization לכאילו Lead Potential.


No False Dead End:
פערים מסווגים לפי START NOW / START + COMPLETE IN PARALLEL / RESPONSIBLE ALTERNATIVE / WAIT / PRESERVE / genuine STOP.


Primary ownership:
Director — integrated Decision Frame.
Media/Budget, Meta, Metrics ויתר domains — תרומה מקצועית בתחומם.
Advisor — recommendation/explanation.


Output:
Campaign Plan/Package ready for user review, כולל unresolved manageable unknowns.


Exit:
המהלך ניתן להצגה ואישור בלי שה־Executor יצטרך להמציא משמעות.


Reopen:
Freshness failure, budget/economics/capacity change, technical impossibility, measurement gap או material contradiction.


4.8 Stage 8 — Campaign Review + User Approval
Purpose:
להראות למשתמש מה באמת עומד להיעשות לפני פעולה חיה.


המשתמש צריך להבין במידה המתאימה:
מה יפורסם;
המשמעות/מסר;
למי/באיזה Scope;
Offer / CTA / destination;
Budget envelope;
Time/Window;
Creative/Assets;
material assumptions/risks;
Measurement intent;
ומה הוא מאשר.


Primary ownership:
Advisor — explanation and professional responsibility.
Experience — approval interaction.
Applicable domains — semantic source.


Authority:
Campaign/Creative/Plan Approval עדיין אינו Execution Authorization אלא אם downstream contract מגדיר במפורש פעולה מורשית וספציפית; בפיילוט נשמרת הפרדה מפורשת.


Evidence writes:
Approved version, user corrections, approval scope.


Exit:
Campaign/Plan approved at the appropriate level.


Reopen:
User requests material change, new evidence or change in scope/budget/meaning.


4.9 Stage 9 — Authorization → Fresh Preflight → Launch → Verified Readback
Purpose:
להפוך פעולה מאושרת לפעולה חיה באופן נאמן, מורשה וניתן לאימות.


Flow:
Approved Professional Intent
→ Explicit Scoped Authorization
→ Fresh Preflight
→ Closed Semantic Action Contract
→ Controlled Execution
→ Receipt
→ Verified Readback where available.


Preflight:
target identity, permissions, dependencies, assets, current state, policy/eligibility, measurement/readback availability ו־new-state conflicts לפי הפעולה.


Execution Orchestration:
מקבל חוזה פעולה מספיק סגור. אינו רשאי לשנות Strategy, Budget, Audience Meaning, Brand Truth או Scope כדי “להצליח טכנית”.


Meta:
מספק current executability/capability/constraint truth.


Failure:
אם אין דרך שקולה במשמעות — Semantic Return. Technical alternative ≠ semantic equivalence.


Evidence writes:
Authorization, preflight state, execution attempts, receipt, readback, final/uncertain state.


Exit:
הפעולה בוצעה והמצב אומת, או נשמר במפורש כ־Unverified/Unknown כאשר Readback אינו אפשרי.


Reopen:
Execution failure, stale state, permission change, non-equivalent path, partial success או readback contradiction.


4.10 Stage 10 — ניהול חי + Lead / Business Realization
Purpose:
לנהל את הפעילות כמערכת שיווקית מתמשכת המחוברת לתוצאות העסק, לא כ־Ads Manager wrapper.


Decision inputs לפי הצורך:
Delivery;
Media/Budget;
Creative;
Meta state;
Offer/destination;
measurement maturity;
lead quality/potential;
response/contact;
qualification;
meeting/quote/opportunity;
won/lost;
contribution/collection;
fulfillment;
capacity/serviceability.


Cross-domain invariant:
Potential Lead Quality ≠ Business Realization Capability ≠ Realized Outcome.


Advisor–User Improvement Loop:
Advisor יכול להפיק Question, Task, Recommendation, Business Intervention, Experiment, Wait, Preserve או Do Nothing כאשר הראיות מצביעות על Bottleneck או Opportunity בעסק/קמפיין.


Material business intervention:
נשמר עם rationale, authority, before/after state ו־measurement lineage. אין לייחס אוטומטית את תוצאתו לקמפיין.


Primary ownership:
Director — current decision framing.
Advisor — recommendation/user relationship.
Media/Budget, Creative, Golden Lead, Metrics, Context, Meta — professional truth לפי תחום.
Execution Orchestration — רק ביצוע מורשה.


Exit:
אין Exit קבוע כל עוד הקשר המתמשך פעיל; Stage זה מייצר Moments שמובילים להחלטה, פעולה, Wait/Preserve או Measurement/Learning.


Reopen:
כל material new evidence, risk, drift, goal change, outcome maturation או contradiction.


4.11 Stage 11 — Measurement → Learning → Next Decision
Purpose:
להפוך את המציאות לראיות, להבין מה מותר להסיק, ולשפר את ההחלטה הבאה בלי לקדם תוצאה לאמת בשקט.


Measurement:
Raw Data ≠ Metric ≠ Outcome ≠ Proxy ≠ Estimand.
Attribution ≠ Incrementality.
Observation ≠ Causation.
Missing/Pending/Censored ≠ Zero.
יש להעדיף את ה־deepest reliable outcome שמתאים להחלטה, לא את העמוק ביותר בכל מחיר.


Learning path:
Result
→ Metrics / Measurement Interpretation
→ Learning Candidate
→ Validation / Scope / Contradiction Review
→ Keep / Strengthen / Split / Demote / Reopen / Retire / New Candidate
→ governed Context and/or Knowledge update according to ownership
→ Next Decision.


Local learning:
יכול לעדכן Context כאשר מדובר באמת מקומית.


Cross-business/general learning:
אינו מועבר אוטומטית. נדרש Scope/Validation/Promotion governance מתאים.


User-facing:
What Works, What We Learned, Goal/Progress, Wait/Preserve, Next Decision לפי הראיות.


Exit:
