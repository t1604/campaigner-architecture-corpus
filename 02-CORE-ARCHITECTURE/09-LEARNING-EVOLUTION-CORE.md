0. PURPOSE


מסמך זה מבצע Reconciliation בין Constitution/Product Truth, GOV-LEARNING-EVOLUTION-001 v0.2 ההיסטורי, Professional Knowledge Foundation, Validation/Evidence System, Advisor–User Improvement Loop, Metrics/Measurement reconciliation, Golden Lead reconciliation ו-Master Development Path-002.


מטרתו לשמור את עקרון האבולוציה המבוקרת בלי להפוך Learning למנגנון Self-Modifying בעל סמכות עצמית.


1. ROLE OF THE CORE


Learning / Evolution Core מחזיק את הדרך שבה תוצאה, תצפית, כשל, הצלחה, סתירה, מומחה, אות, ניסוי או שינוי הופכים באופן מבוקר ל:
- Evidence;
- Learning Candidate;
- Hypothesis/Pattern/Knowledge candidate;
- local understanding update;
- proposal to preserve/change/reopen;
- scoped promotion/demotion/retirement candidate;
- verified propagation where authority permits.


Learning exists to improve the next decision and, over time, the professional system itself.


2. WHAT LEARNING IS NOT


Learning is not:
- raw data collection;
- Metrics;
- Knowledge/Evidence registry by itself;
- a self-authorizing policy engine;
- autonomous Constitution/Core editor;
- “whatever happened after a change”;
- an excuse to generalize one client to all clients;
- an optimization loop that maximizes one metric;
- a license to use client data outside permitted purpose/scope.


3. CONSTITUTIONAL ROOT — LEARNING IS NOT AUTHORITY


Learning can generate:
Evidence / Hypothesis / Pattern Candidate / Metric Candidate / Rule Candidate / Knowledge Candidate / Product Candidate.


It cannot silently convert any of them into:
Constitutional Truth / Product Truth / Domain Truth / Build Authority / Runtime Authority / expanded permission.


No Self-Modifying Constitution.
No Silent Promotion.
No Silent Scope Expansion.
No Silent Authority Expansion.


4. LEARNING LOOP — CORE CANDIDATE


A meaningful learning cycle preserves at least:
Observation / Result / Signal
→ Data/Measurement Quality Check
→ Evidence
→ Alternative Explanations / Contradictions
→ Hypothesis / Learning Candidate
→ Test / Intervention / Additional Evidence / Wait
→ Outcome
→ Conclusion with Confidence + Scope
→ KEEP / STRENGTHEN / SCOPE-SPLIT / DEMOTE / REOPEN / RETIRE / NEW CANDIDATE
→ Next Decision.


Not every cycle requires an experiment. The evidence method must fit the claim and decision.


5. THREE LEARNING DIRECTIONS


Learning must support all three, not only failure correction:


A. PRESERVE / STRENGTHEN WHAT WORKS
Identify evidence-backed behaviors/mechanisms worth retaining.


B. CORRECT / REDUCE HARM OR ERROR
Detect failure, misunderstanding, weak process, invalid proxy, stale knowledge or harmful intervention.


C. DISCOVER / EXPAND CAPABILITY
Identify a missing distinction, knowledge family, signal, intervention or product capability that may add meaningful value.


“More changes” is not a success metric for Learning.


6. LEARNING EVENT


A learning event may be triggered by:
- unexpected success;
- failure;
- contradiction;
- user correction;
- new local evidence;
- new external evidence;
- expert input;
- campaign/creative result;
- Sales/CRM outcome;
- business intervention;
- platform change;
- missing measurement;
- drift;
- inability to reproduce a prior result.


The event itself is not the conclusion.


7. LOCAL LEARNING ≠ CROSS-BUSINESS LEARNING ≠ PRODUCT LEARNING


Learning scope must remain explicit.


LOCAL LEARNING:
what was learned about this User/Business/Offering/Account/context.


CROSS-BUSINESS LEARNING:
a scoped mechanism/pattern/prior candidate that may be useful elsewhere under transfer governance.


PRODUCT/SYSTEM LEARNING:
what Campainer learns about its own decision process, interfaces, knowledge gaps, mechanisms, measurement or UX.


A local result does not automatically climb these levels.


8. TRANSFER GOVERNANCE


Cross-business learning must preserve:
- source scope;
- target scope;
- mechanism rationale;
- evidence maturity;
- counterexamples;
- scope differences;
- privacy/permission status;
- local validation need;
- negative-transfer risk;
- freshness/drift/reopen trigger.


Cross-business learning may create better priors/questions/candidates.
It does not auto-create target-local truth, predictor threshold or execution gate.


9. PRIVACY / PURPOSE / DATA-MINIMIZATION


Learning from client/customer/user data is constrained by purpose, permission, law and policy.


Client-local data does not become cross-client training material merely because it exists.


No identifiable client/customer data may be exposed into another client’s decision context without legitimate permission and architecture.


A user may restrict permitted use; such restriction must be respected in learning propagation.


Learning value never changes a user’s rights or quality of service.


Exact cross-client learning policy remains Owner/Privacy governance work.


10. EVIDENCE BEFORE PROMOTION


A candidate’s maturation depends on the claim type and scope.


A useful conceptual ladder:
Observation
→ Candidate
→ Supported Prior/Scoped Pattern
→ Decision-Support Ready in scope
→ Replicated/Validated in scope
→ Promotion Proposal where governance allows.


Exact states/labels are not fixed here.


Occurrence count alone is not maturity.
Source prestige alone is not maturity.
One successful case is not broad truth.


11. CONTRADICTION / NEGATIVE CASES


Learning must actively retain:
- failed experiments;
- null findings;
- reversals;
- counterexamples;
- local evidence that conflicts with a prior;
- scope-specific effects;
- implementation failures;
- measurement failures.


A model that stores only successes cannot learn reliably.


Contradiction may lead to:
SCOPE SPLIT / LOWER CONFIDENCE / NEW MODERATOR / REOPEN / RETIRE / NEW HYPOTHESIS.


12. CAUSAL DISCIPLINE


Learning consumes Measurement’s evidence class and causal limitations.


Result After Change ≠ Result Caused By Change.
Attribution ≠ Incrementality.
Prediction ≠ Treatment Effect.


When causal design is weak, Learning may record association/hypothesis but must not promote causal rule language.


13. INTERVENTION LEARNING


Campaign, Creative, Media, Sales, Offer, CRM, Capacity and other business changes can all be interventions.


Learning should know, through the shared lineage:
- problem/hypothesis;
- baseline;
- actor/authority;
- change/treatment;
- timing;
- exposure/implementation state;
- outcomes;
- concurrent changes;
- uncertainty;
- result;
- preserve/change/rollback/reopen.


A business-side improvement can be a legitimate source of learning even if Meta campaign settings were unchanged.


14. IMPLEMENTATION QUALITY ≠ KNOWLEDGE QUALITY


A good hypothesis can fail because implementation was poor.
A technically successful implementation can operationalize the wrong idea.


Learning must distinguish:
- conclusion/evidence quality;
- implementation fidelity;
- adoption/usage;
- downstream outcome.


“Knowledge was written somewhere” is not proof it was correctly activated/used.


15. PROPAGATION / IMPACT MAP


Before a material learned change is propagated, identify affected consumers/objects:
- Knowledge/Evidence;
- Complete User Context;
- Director;
- Advisor;
- Golden Lead;
- Metrics;
- Strategy/Creative;
- Meta/Execution;
- Experience;
- future decisions/tests.


A change must not be “fixed in one document” while old semantics remain active elsewhere.


This is the learning equivalent of Semantic Handoff.


16. VERIFICATION AFTER PROPAGATION


A promoted/implemented change is not complete merely because it was updated.


Where material, verify:
- intended consumers received the new version;
- old/stale projections were invalidated;
- behavior changed as intended;
- no unexpected harmful side effect appeared;
- the change still respects authority/privacy/scope;
- rollback/reopen remains possible.


17. FRESHNESS / DRIFT / REOPEN


Learning must keep knowledge and mechanisms reopenable.


Reopen triggers include:
- changed platform;
- changed market/regulation;
- changed Offering/business process;
- changed CRM semantics;
- new contrary evidence;
- failure to replicate;
- performance drift;
- changed user goal/capacity;
- changed data quality;
- changed permissions.


No mechanism receives permanent immunity because it worked previously.


18. META-LEARNING


Campainer may learn about the quality of its own learning/validation processes, but recursion must remain bounded and governed.


Examples:
- whether a confidence process overestimates certainty;
- whether certain gaps repeatedly appear too late;
- whether a consumer fails to use supplied knowledge;
- whether a validation route costs more than the decision value it creates.


Meta-learning cannot bypass constitutional/Owner authority.


19. UNKNOWN UNKNOWNS / GAP DISCOVERY


Learning should not only validate known hypotheses; it should be able to surface:
- missing signals;
- missing metrics;
- unexplained residual patterns;
- repeated corrections;
- recurrent failures with no owned mechanism;
- systematic disagreement between owner belief and outcomes;
- blind spots exposed by negative cases.


Discovery creates a candidate/gap, not an automatic new mechanism.


20. COST OF LEARNING


Before collecting more data or opening an experiment, consider:
- decision value;
- money;
- time;
- user burden;
- operational burden;
- privacy;
- risk;
- maintenance complexity;
- opportunity cost;
- reversibility.


Learning that cannot plausibly change a decision or recurring capability does not justify unlimited collection.


21. RELATION TO KNOWLEDGE / EVIDENCE


Knowledge/Evidence owns epistemic representation of Claims/Evidence/Priors/Contradictions/Gaps.
Learning owns the controlled lifecycle by which new results/candidates may change that knowledge over time.


Open architecture question:
exact ownership of the persistent Knowledge registry versus Promotion workflow.


22. RELATION TO COMPLETE USER CONTEXT


Complete User Context owns local state/history and local learned understanding about the specific business/user.


Learning can generate a candidate local update, but local truth changes must preserve source, correction, scope and history.


Cross-business propagation is separate.


23. RELATION TO METRICS


Metrics defines what was measured and what may be inferred.
Learning consumes that evidence and decides what candidate learning it supports.


Learning must not relabel INCONCLUSIVE as “weak success” merely to keep momentum.


24. RELATION TO DIRECTOR / ADVISOR


Director/Advisor use current approved/local knowledge in decisions.
They may generate observations, questions and candidate learning.
They do not self-promote a local insight to general policy.


Advisor may tell the user “we learned X about your business” when local evidence supports it, separately from “we have evidence this is generally true.”


25. RELATION TO GOLDEN LEAD


Golden Lead outcomes and business realization are major feedback sources.


Learning should distinguish:
- better prediction of high-value opportunities;
- better realization of the same opportunity quality;
- better incremental media influence;
- better access/retrievability;
- better business outcome/economics.


Do not collapse all improvement into a Golden score.


26. PILOT AS LEARNING ENGINE


The controlled pilot is expected to create local/CV-007+ evidence, not merely verify build stability.


Priority learning targets include:
- real Golden predictors;
- lead handling realization;
- qualification/friction false positives/negatives;
- route performance;
- response sensitivity;
- Creative Job state change;
- Proof Fit;
- signal readiness;
- capacity/economics;
- external-signal decision value;
- cross-business transfer failures.


Pilot results remain scoped until the relevant promotion gate is met.


27. HUMAN REVIEW IN PILOT


For the pilot, material learning-driven changes should remain under Human Review according to authority/risk.


A candidate being well-supported does not mean it can automatically change:
- campaign strategy;
- business process;
- budget;
- Brand Truth;
- user permissions;
- Core/Constitution;
- cross-business policy.


28. PRESERVE WHAT WORKS


Learning must actively produce positive preservation candidates, not only changes.


A Preserve candidate should state:
- what behavior/mechanism appears to work;
- outcome/scope;
- evidence;
- uncertainty;
- what remains unproven;
- what would reopen the decision.


No empty praise or gamification.


29. RETIREMENT / ROLLBACK


Knowledge, mechanism or policy may be:
- demoted;
- scope-split;
- deprecated;
- retired;
- rolled back;
- replaced.


History and rationale remain traceable.


Removal should consider active consumers/dependencies so retirement does not create orphan behavior.


30. DO-NOT-PROMOTE


Do not promote automatically:
- one case → general rule;
- one experiment → universal rule;
- association → cause;
- user belief → buyer truth;
- platform suggestion → marketing truth;
- local threshold/weight → cross-client rule;
- repeated occurrence → maturity without independence/scope/evidence;
- prediction accuracy → treatment policy validity;
- “works here” → “works everywhere”;
- copied document/update → verified implementation;
- high maturity → execution authority;
- learning candidate → Core change.

32. RECONCILIATION DISPOSITION


KEEP / CORE CANDIDATE FROM GOV-LEARNING-EVOLUTION:
- continuous controlled improvement;
- learning is more than data collection;
- preserve/correct/discover three-direction model;
- evidence/contradiction/falsification discipline;
- implementation quality distinct from conclusion quality;
- privacy/authority boundaries;
- rollback/reopen/version history;
- learning value judged by improved decisions/user value, not number of rules;
- bounded meta-learning;
- signals/activation and gap discovery.


EXPAND FROM PROFESSIONAL KNOWLEDGE + CURRENT CORES:
- explicit Local vs Cross-Business vs Product Learning;
- T0–T6 transfer governance integration;
- Baseline/Intervention/Concurrent-change lineage;
- Golden Potential vs Realization vs Incremental Opportunity distinction;
- Pilot as CV-007+ evidence engine;
- user-facing “what I learned about your business” semantics;
- Preserve/Wait/Inconclusive.


SPLIT / RECLASSIFY:
- Knowledge registry semantics → Knowledge/Evidence;
- metric definitions/causal confidence → Metrics;
- local state → Complete User Context;
- decision/action selection → Director/Advisor;
- runtime mechanism orchestration → Execution Orchestration;
- old all-mechanism registry/recursive self-optimization machinery → Architecture candidates, not Core truth.


REJECT AS CORE TRUTH:
- autonomous self-modification;
- occurrence-count promotion;
- unlimited recursive meta-mechanisms;
- automatic learning from all available user/client data;
- automatic policy change from successful local result;
- optimization of one metric over constitutional/product purpose.

The historical doctrine contains strong foundations, but its broad mechanism-registry architecture should be narrowed: Core defines controlled learning/evolution; exact mechanism graph, schemas and automation belong to Architecture/Build.


Pilot/local evidence remains the intended source of calibration and does not block defining the Learning truth boundary.
