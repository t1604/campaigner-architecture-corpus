0. PURPOSE


מסמך זה מבצע Reconciliation ל-Experience / Interface על בסיס Product Truth, Advisor Core, Complete User Context reconciliation, Director reconciliation, Advisor–User Improvement Loop, Professional Knowledge user-facing semantics והדיונים המאוחרים על UX/Progressive Diagnosis/Baseline/Lead Handling.


המסמך מגדיר עקרונות חוויה ומשמעות, לא Screens/Navigation/UI implementation.


1. ROLE OF THE CORE


Experience / Interface Core מחזיק כיצד Campainer מציגה ומאפשרת אינטראקציה עם אמת, החלטה, Advisor, משימה, סטטוס, אישור, התקדמות ולמידה — באופן שמקיים רציפות של מערכת מקצועית אחת ומאפשר לאדם להבין, לבחור, לתקן ולפעול.


Experience owns the presentation/interactivity layer.
It does not own the professional truth or decision that it presents.


2. SAME ADVISOR / ONE PROFESSIONAL CONTINUITY


מבחינת המשתמש יש Advisor מקצועי אחד ורציף.


המשתמש אינו נזרק בין Intake Bot, Strategist, Creative Bot, Meta Bot, Analyst וכו'.


מאחורי הקלעים רכיבים/בעלי תפקידים שונים יכולים לעבוד; Experience מחברת אותם לחוויה קוהרנטית שבה:
- מה שנאמר קודם זכור בהקשר הנכון;
- החלטות והתחייבויות ממשיכות;
- שינוי מוסבר;
- שאלה חדשה מחוברת לסיבה;
- תוצאה מחוברת למה שבוצע;
- למידה מחוברת להחלטה הבאה.


Same Advisor is professional continuity, not just avatar/name consistency.


3. CHAT IS A MAJOR INTERFACE, NOT THE WHOLE PRODUCT


Conversation is a central interaction surface, but Campainer need not be Chat-only.


Professional work may be better represented through:
- conversation;
- work cards;
- structured context views;
- task/progress surfaces;
- comparison/decision views;
- approval surfaces;
- asset/studio workspaces;
- measurement/learning views.


Core principle:
The interface form may vary; the user should still experience one coherent Advisor and one continuous work relationship.


4. THE CENTER IS WORK, NOT A DASHBOARD OF NUMBERS


Experience should not reduce Campainer to charts/metrics-first SaaS.


A strong user-facing working model is a shared professional workbench centered on:
- What is happening now?
- What does Advisor understand?
- What does Advisor recommend?
- What does Advisor need from me?
- What are we testing?
- What is working / what should we preserve?
- What did we learn?
- Are we progressing toward the actual goal?


Exact labels/UI are Working, not Core truth.


5. USER-FACING SEMANTIC FAMILIES


Candidate semantic families that recur across domains:


QUESTION
A decision-relevant information gap and why it matters.


TASK / ACTION REQUEST
A concrete thing the user/business should do, with reason, scope and expected completion evidence.


RECOMMENDATION
Advisor’s professional position, why, assumptions/risks and what would change it.


DECISION / CHOICE
A bounded choice the user is making, distinct from discussion or recommendation.


APPROVAL / AUTHORIZATION
Explicit approval for a specified material action; not inferred from payment, discussion or vague assent.


WHAT WE ARE TESTING
Hypothesis/mechanism, what may be learned and what outcome matters.


WHAT WORKS / PRESERVE
Evidence-backed local behavior/process/message/asset that should currently be retained.


WHAT I LEARNED ABOUT YOUR BUSINESS
New local understanding, source/evidence/confidence and what changed in the model/next decision.


GOAL / PROGRESS
Movement toward locally authorized business/Golden outcome, not media vanity metric.


WAIT / MONITOR / DO NOTHING
A positive professional state with rationale and reopen condition.


WARNING / BLOCKER / GAP
What is missing/risky/blocked, why, and the path forward where one exists.


Exact product entities/names remain Architecture.


6. QUESTIONS MUST EARN USER ATTENTION


Experience should expose questions only when the answer can materially improve a current/future professional decision.


Questions should be:
- understandable;
- scoped;
- one decision need at a time where possible;
- accompanied by “why this matters” when not self-evident;
- skipped when the information already exists or can be responsibly acquired elsewhere;
- adaptive based on prior answers/evidence;
- allowed to end when Minimum Sufficient Understanding is reached.


No fixed 45/60-question deep diagnosis is Core truth.


7. PROGRESSIVE DIAGNOSIS EXPERIENCE


The diagnosis experience should embody:
short diagnosis
→ initial professional value
→ bounded deeper diagnosis
→ first responsible campaign/action
→ measurement/learning
→ targeted deeper questions when reality makes them valuable.


The user should not experience “you must finish understanding your entire business before Campainer can help.”


Unknowns can remain visible and managed.


8. REFLECTION BEFORE FIXING


When Campainer inferred a material understanding that will change strategy, goal, classification or meaningful action, Experience must provide an appropriate way to reflect/verify/correct it.


Example semantic form:
“What I understand now is X, mainly because of Y. Is that right?”


This is impact/uncertainty-triggered, not a ritual after every message.


9. BASELINE SNAPSHOT / “WHERE WE STARTED”


Experience should be able to make relevant baseline understandable to the user when it matters:
- what was true before intervention;
- which parts are user-stated vs measured;
- what was unknown;
- what changed later.


The user need not see a technical audit dump.


Core value:
prevent false narratives like “the campaign caused everything” when the business/sales/offer/CRM also changed.


Exact visualization is not Core truth.


10. LEAD HANDLING / BUSINESS SIDE EXPLANATION


When campaign success depends on what happens after a lead arrives, Experience should explain this partnership clearly rather than silently blaming business or advertising.


Advisor can explain:
- advertising can bring the right opportunity;
- the business then needs to respond/track/qualify/follow up appropriately;
- without outcome tracking Campainer may not know whether the problem was acquisition or realization;
- therefore understanding the lead-handling system is part of responsible campaign work.


Absence of CRM may result in a Task/parallel improvement rather than automatic dead end.


11. TRUTH / CONFIDENCE / SOURCE COMMUNICATION


User-facing explanation should, when decision-relevant, distinguish:
- measured here;
- stated by you/business;
- learned elsewhere;
- professional prior;
- hypothesis here;
- prediction;
- unknown;
- contradicted/stale.


Do not bury every response under epistemic labels; expose the distinction proportionally to its effect on trust/choice/action.


No false certainty to simplify UI.


12. RECOMMENDATION EXPERIENCE


Advisor is not a menu.


A recommendation surface should be able to carry:
What I see
→ What it means
→ What I recommend
→ Why
→ Main assumptions/risks/unknowns
→ What would change my recommendation
→ What you need to decide/do next.


Alternatives may be shown without removing professional stance.


13. CHOICE / CONSENT / AUTHORIZATION


Experience must distinguish conversation states from execution authority.


Question / discussion / idea / inclination / “sounds good” / payment / strategy approval are not automatically external-write authorization.


For a material action, the approval surface should make clear:
- what will happen;
- what object/scope;
- key cost/risk where material;
- whether it changes live state;
- what the user is authorizing.


Exact confirmation UX and risk tiers remain Architecture.


14. NO FALSE DEAD END EXPERIENCE


Do not present ordinary gaps as “you cannot continue” when a responsible alternative exists.


Experience should distinguish:
- can start now;
- start and complete in parallel;
- start with responsible alternative;
- user/business action needed;
- external provider action needed;
- wait for outcome/review;
- genuine stop.


A blocked state should explain why and the next responsible path.


15. TASKS / USER ACTIONABILITY


Tasks should not become an unranked Jira board imposed on a small-business user.


A user-facing task should communicate:
- exact action;
- why Advisor needs/recommends it;
- which goal/decision it supports;
- priority/timing when real;
- who should do it;
- what “done” means;
- whether an alternative exists.


When one clear next action is enough, show one clear next action rather than a wall of work.


16. USER WORKBENCH — WORKING EXPERIENCE CONCEPT


The workbench may organize the relationship around:
- Questions;
- Tasks;
- Recommendations;
- Decisions/Approvals;
- What We Are Testing;
- What Works;
- What I Learned;
- Goals/Progress;
- Open Gaps/Wait states.


These are semantic candidates, not mandatory navigation tabs/screens.


17. WHAT WORKS / POSITIVE REINFORCEMENT


Experience should not contact the user only when something is wrong.


When evidence supports it, Advisor can explicitly reinforce:
- good lead handling;
- useful proof/assets;
- consistent lost-reason tracking;
- appropriate capacity discipline;
- working creative/message/route;
- measurement improvement;
- correct decision not to change.


The message must explain evidence/meaning/uncertainty, not provide empty praise/gamification.


18. WHAT I LEARNED ABOUT YOUR BUSINESS


This should present local learning as change in understanding, for example:
Before: working hypothesis X.
New evidence: Y.
Now: understanding Z with confidence/scope.
Next implication: decision/question/action.


It must distinguish local learning from cross-business knowledge.


The user can correct it.


19. GOALS / PROGRESS


Progress is relative to locally authorized goals, not “more” universally.


Experience may need to show:
- current state;
- desired state/goal;
- baseline/window;
- direction/magnitude where meaningful;
- outcome maturity/coverage;
- uncertainty;
- concurrent business changes;
- next decision.


Possible semantic states such as IMPROVING / STABLE-PRESERVED / MIXED / NOT-YET-MATURE / INSUFFICIENT-EVIDENCE / OFF-TRACK may remain Working; no universal thresholds.


20. ERRORS / CORRECTIONS


When Campainer was materially wrong, Experience should not silently edit history.


Advisor behavior:
acknowledge
→ correct
→ explain effect
→ update model/decision/action
→ continue.


User correction must reach underlying Context/Decision, not remain cosmetic chat text.


21. MULTI-BUSINESS CONTEXT


Experience must make active Business/Brand/Offering context sufficiently clear where confusion is possible.


Same user and same Advisor do not justify mixed assets, economics, customers or Strategy across businesses.


Switching context should preserve continuity without contamination.


Exact navigation/switcher UI remains implementation.


22. STUDIO EXPERIENCE BOUNDARY


Brand Asset Studio and Campaign Creative Studio are distinct workspaces/semantic responsibilities but should feel like one Campainer system.


Brand side:
identity/source/assets/rights/readiness/gaps.


Creative side:
creative job/concepts/variants/production/measurement.


User should see why an asset request or approval matters to the campaign rather than being moved into a disconnected design tool.


23. OPERATIONAL STATUS VS ADVISOR VOICE


System can provide operational status/receipt without pretending Advisor personally authored a message that is purely automated.


Experience may differentiate:
- Advisor professional communication;
- system operational status;
- execution receipt/error;
while maintaining product coherence.


24. ALERTS / RETURNS


Do not generate notifications merely to look active.


Value-driven return is justified by:
- material new evidence;
- meaningful change;
- risk;
- required decision/approval;
- outcome maturity;
- reopened gap;
- useful synthesis;
- user commitment/task due when relevant.


Exact notification/cadence mechanics are not Core truth.


25. ACCESSIBILITY / MOBILE / HEBREW RTL


Experience must not lose professional meaning because of screen/form factor.


Readability, RTL, mobile interaction and accessibility requirements are legitimate constraints.


Exact visual standard/threshold belongs Design/Build/Accessibility governance.


26. PRIVACY / CONTROL SURFACES


Where material, Experience should provide understandable ways to:
- see/correct information;
- change goal;
- object/restrict use;
- review permissions/approvals;
- stop/exit;
- export/port owned information/assets where applicable.


The interface should not hide consent inside ordinary continuation.


27. DO-NOT-PROMOTE


Do not promote:
- Dashboard = product;
- Chat-only = product truth;
- one screen/navigation architecture;
- fixed number of diagnosis questions;
- fixed progress percentage formula;
- gamification/praise as default behavior;
- all system status as Advisor-authored conversation;
- click/engagement as goal;
- hidden consent;
- full truth/evidence dump to every user at every moment;
- same UX depth for every user/decision;
- activity/notification volume as value.

29. RECONCILIATION DISPOSITION


KEEP / CORE CANDIDATE:
- same continuous Advisor experience;
- presentation ≠ professional truth ownership;
- Chat is interface, not whole product;
- workbench rather than metrics-first dashboard;
- question/task/recommendation/decision/approval distinctions;
- user-facing testing/learning/preserve/progress semantics;
- Reflection Before Fixing;
- Progressive Diagnosis experience principle;
- explicit authority surfaces;
- No False Dead End presentation;
- correction/control;
- context isolation;
- value-driven return.


EXPAND:
- Baseline explanation;
- business-side lead handling explanation;
- what-we-learned local model;
- Preserve What Works communication;
- Studio/Advisor continuity.


KEEP WORKING / ARCHITECTURE:
- exact screens/navigation;
- exact workbench object model;
- exact approval UX;
- exact labels/states;
- exact chat/card/panel mix;
- exact mobile/RTL design.


REJECT AS CORE TRUTH:
- dashboard-first SaaS identity;
- fixed long questionnaire;
- one universal UI flow depth;
- hidden consent;
- gamification as professional reinforcement;
- fragmented user-facing agents.


30. PROVISIONAL VERDICT


Experience / Interface domain is ready for Core review at the principle level.


The current evidence does not justify freezing screens or navigation. It does justify a coherent experience architecture centered on one continuous Advisor, professional work objects, bounded diagnosis, explicit choices/approvals, visible learning and user control.
