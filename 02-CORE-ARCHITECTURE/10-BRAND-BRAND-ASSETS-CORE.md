0. PURPOSE


מסמך זה מבצע Reconciliation ל-Brand / Brand Assets לאחר Professional Knowledge Foundation P1, Wave A context/knowledge/director/measurement/learning reconciliation ו-Advisor Core המאושר.


Brand אינו Strategy Engine ואינו Creative Director. הוא מחזיק את הזהות הציבורית המורשית, Brand Truth, נכסים, גרסאות, זכויות, הסכמה, Provenance, Scope, Inheritance ו-Readiness לשימוש נתון.


1. ROLE OF THE CORE


Brand / Brand Assets Core אחראי לכך שקמפיינר תדע:
- מהי אמת המותג המאושרת ולמי/לאיזה Business/Brand/Offering היא שייכת;
- אילו נכסים קיימים ומה תפקידם;
- מהו מקור/מאסטר ומהו derivative;
- מה ניתן להשתמש בו, לאיזה שימוש, באיזה Scope ובאילו מגבלות;
- מה חסר ומה ניתן להשלים בלי להמציא אמת;
- מה מוגן משינוי ומה ניתן להתאים;
- מתי Creative/Production/Meta מקבלים Snapshot תחום;
- איך שינוי Campaign עשוי להציע Brand Change Candidate בלי להפוך אוטומטית ל-Brand Truth.


2. ROOT DISTINCTIONS


Brand Knowledge ≠ Strategy.
Brand Knowledge ≠ Creative Judgment.
Brand Truth ≠ Brand Asset.
Brand Asset ≠ Campaign Creative.
Proof Requirement ≠ Proof Asset.
Creation ≠ Source of Truth.
Asset existence ≠ Asset readiness.
Consistency ≠ performance proof.
Rights ≠ Consent ≠ Provenance ≠ Trademark Permission ≠ Privacy/Confidentiality Permission.
Same user/owner ≠ cross-business permission.
Parent/group relationship ≠ automatic inheritance.
Winning campaign asset ≠ permanent Brand Truth.


3. BUSINESS / BRAND / OFFERING SCOPE


A user may own multiple businesses.
A business may contain Brands, locations and Offerings.


Default rule:
No automatic leakage of Brand Truth, assets, proof, preferences or learned creative patterns between separate businesses.


Inheritance requires:
- explicit relationship;
- authority;
- scope;
- rights/consent compatibility;
- stated inheritance rule;
- local validation where the inherited object is contextual rather than mandatory identity truth.


OWNER PRINCIPLE RESOLVED BY D04: default NO cross-business inheritance; parent/group inheritance requires explicit governed relationship, rights compatibility and scope. Exact hierarchy/inheritance schema remains Architecture work.


4. BRAND TRUTH


Brand Truth is an authorized, scoped statement about public identity/positioning expression/identity constraint that Campainer is expected to preserve until corrected/replaced through governance.


Potential families include:
- identity/name;
- approved positioning expression provided from Strategy/authority;
- verbal identity/tone constraints;
- visual identity constraints;
- logo/system;
- color/type systems;
- photography/video style where genuinely authorized;
- approved claims/credibility expressions;
- protected identity rules;
- allowed/forbidden variations.


Exact universal Brand Identity field set is not promoted.


Observed repetition alone does not become Brand Truth. It may be an inferred style candidate requiring owner/brand authority confirmation.


5. POSITIONING EXPRESSION BOUNDARY


Strategy/Advisor/Director determine strategic positioning/value/claim direction.
Brand may hold an approved Positioning Expression record for reuse and consistency.


Brand does not originate or silently alter Strategy.
If a desired brand expression requires strategic repositioning, return to the decision path.


6. ASSET ROLES


Useful conceptual roles:
- SOURCE / MASTER ASSET;
- APPROVED REUSABLE BRAND ASSET;
- PROOF ASSET;
- DERIVATIVE;
- CREATIVE ASSET;
- CAMPAIGN CREATIVE;
- BRAND CHANGE CANDIDATE.


One file may serve multiple roles, but roles keep separate semantics.
Example: a customer case can be reusable Brand Asset + Proof Asset, but each intended claim/use still needs fit, scope, rights and consent checks.


7. SOURCE → MASTER → DERIVATIVE → USAGE LINEAGE


Material assets should preserve enough lineage to answer:
- where did it come from;
- who created/provided it;
- which version is authoritative;
- what transformations occurred;
- what is approved versus generated/derived;
- where it was used;
- which restrictions/permissions apply.


Latest modified file is not automatically master.
Generated or recreated media does not become Source-of-Truth simply because Campainer created it.


8. ASSET READINESS IS INTENDED-USE SPECIFIC


Readiness should be multidimensional, not a single global score.


Candidate readiness dimensions:
- correct Business/Brand/Offering scope;
- authority/source/version;
- provenance;
- copyright/license;
- likeness/testimonial consent;
- privacy/confidentiality;
- trademark/third-party permissions;
- proof/claim fit;
- Brand fit;
- technical quality;
- accessibility/legibility where relevant;
- platform/intended-use fit;
- freshness;
- restrictions.


An asset may be ready for one use and not another.
No universal readiness score or mandatory asset count is promoted.


9. PROOF ASSETS


Proof selection starts from Buyer Question / Claim / Risk-Trust Object, not from “we have testimonials.”


Brand manages availability/readiness/rights/provenance of proof assets.
Strategy/Creative decide whether and how a proof type is professionally needed within their authority.


Proof asset existence does not prove:
- relevance to this claim;
- representativeness;
- recency;
- permission for this use;
- causal effectiveness.


10. RIGHTS / CONSENT / PROVENANCE


Separate evidence axes are mandatory at principle level.


Copyright/license authority does not establish likeness/testimonial consent.
Consent does not establish trademark permission.
Possession of file does not establish usage rights.
Provenance/authenticity metadata does not establish claim truth.


Jurisdiction/sector-specific sufficiency remains Legal/Privacy interface work.
C2PA/IPTC or other technologies are implementation candidates, not Core requirements by name.


11. MISSING ASSET / NO FALSE DEAD END


Missing ordinary assets do not automatically block a campaign.


Evaluate the JOB first:
- Is the asset truly necessary for the professional job?
- Does another approved asset satisfy it?
- Can a truthful derivative/new asset be created?
- Can a different representation satisfy the same job?
- Can work start while the asset is completed in parallel?
- Does cost/risk exceed decision value?


Valid alternatives can include:
- exact text brand name while logo source is recovered;
- temporary licensed/system typography that is explicitly not Brand Truth;
- licensed generic imagery when no real-proof claim is implied;
- different truthful format when video is missing;
- different proof family when a testimonial is missing and another evidence source answers the Buyer Question.


Prohibited:
- fabricated testimonial;
- simulated outcome proof;
- AI-generated portfolio masquerading as real work;
- recreated identity silently promoted to Brand Truth.


12. BRAND SNAPSHOT / PROJECTION


For Campaign/Creative work, Brand should provide a scoped, versioned, minimum sufficient Brand Snapshot rather than expose the full asset universe.


Candidate semantics:
- Business/Brand/Offering scope;
- approved identity/positioning expression;
- protected elements;
- permitted variation;
- approved assets and current versions;
- proof assets with claim/scope/limitations;
- rights/consent/provenance status;
- relevant gaps;
- restrictions;
- freshness;
- return conditions.


Exact payload remains Interface/Architecture work.


13. PROTECTED CHANGE


Not every creative variation is a Brand change.
Not every Brand change should require the same approval.


Potential protected categories include identity/name/logo/core verbal/visual rules, permanent positioning expression, claim rules, parent/inheritance rules and other owner-designated protected truth.


OWNER PRINCIPLE RESOLVED BY D03: material permanent identity/name/logo/core positioning/claim-rule/inheritance changes require explicit higher approval; ordinary surface variation is allowed inside approved freedom. Exact protected-class list/levels remain Build-contract work.


Creative may vary execution surfaces inside approved freedom.
If a creative solution requires a protected Brand change, it must return a Brand Change Candidate rather than silently alter Brand Truth.


14. CAMPAIGN → BRAND LEARNING


Campaign/Creative evidence may nominate:
- a working surface pattern;
- new asset candidate;
- revised style hypothesis;
- proof candidate;
- potential Brand rule/change.


It cannot auto-promote any of these to permanent Brand Truth.


Promotion requires the appropriate Brand/Owner/Learning governance, with scope, evidence, counterevidence, rights and reopen conditions.


15. PRESERVE WHAT WORKS


Preserve identity/assets/rules when:
- authoritative/current;
- rights/scope are valid;
- local evidence supports their intended recognition/identity/proof job or stable process;
- no stronger contradiction/context change exists.


Do not replace functioning identity merely because another business or generic aesthetic prior looks “better.”


Preserve can still permit surface variation when protected core remains stable.


16. EXTERNAL PROFESSIONAL / CONTRACTOR BOUNDARY


External designers, photographers, videographers, editors, voice talent, UGC creators or other specialists receive a minimum sufficient scoped package.


Access should be minimized to what their task requires.


A provider may create/transform assets under contract but does not gain authority to:
- define Brand Truth;
- change Strategy;
- reuse client assets outside permitted scope;
- infer cross-business sharing.


Completion requires deliverable + source/rights/lineage evidence as appropriate, not “done” alone.


17. CREATIVE BOUNDARY


Creative consumes Brand Snapshot/constraints/assets and owns creative representation/execution inside allowed freedom.


Creative may return:
- derivatives;
- new asset candidates;
- missing asset/proof requests;
- Brand change candidates;
- rights/provenance issues;
- evidence about what should be preserved/reopened.


Creative does not silently alter protected Brand Truth.
Brand does not choose Creative mechanism merely because an asset exists.


18. META / TECHNICAL BOUNDARY


Meta/Technical may validate:
- technical asset compatibility;
- placement/spec constraints;
- upload/readback state;
- platform policy/capability.


It does not own Brand Truth.
Platform approval does not establish legal/brand/truth approval.


19. METRICS / LEARNING BOUNDARY


Metrics may link:
Asset/Brand Snapshot/Creative Job/Usage
→ measured outcomes.


Learning may produce preserve/change candidates.


Neither performance nor repeated usage automatically promotes Brand Truth.


20. USER / BUSINESS ACTIONABILITY


When the user/business is the best source, request the smallest useful action with explanation, such as:
- identify correct business/brand/scope;
- upload source/master;
- select authoritative version;
- provide guide/logo/source files;
- provide permission/release/license evidence;
- clarify whether observed style is intentional;
- define parent/group sharing intent;
- mark asset superseded/revoked.


Business authority may be required for identity changes, inheritance, permission acquisition or permanent brand rules.


A gap is not user failure.


21. TRANSFERABILITY


Default: no automatic cross-business Brand Truth/asset transfer.


Structure/ontology can transfer broadly.
Domain patterns may create priors.
Parent/group inheritance requires explicit governed relationship and permissions.
Business-specific evidence/Brand Truth stays local unless transfer is explicitly authorized.


Any cross-business transfer proposal should identify source, target, relationship, evidence, rights, what is/not transferred, local validation need and decision authority.


22. FRESHNESS / REOPEN


Recheck after:
- rights/consent expiry/revocation;
- new authoritative master/source;
- identity/guideline change;
- business/brand ownership/relationship change;
- proof becomes stale/contradicted;
- territory/channel/use changes;
- technical/accessibility requirements change;
- campaign-derived candidate is proposed for permanent adoption.


No universal calendar freshness threshold is required.


23. DO-NOT-PROMOTE


Do not promote automatically:
- universal Brand Identity field set;
- numeric readiness score;
- universal asset checklist/count;
- universal quality threshold;
- universal visual/verbal formula;
- universal color-emotion map;
- universal font/logo/photo/video hierarchy;
- universal proof-source ranking;
- automatic parent/group cascade;
- automatic cross-business sharing;
- campaign winner→Brand Truth;
- file possession→rights;
- provenance→claim truth;
- creation→authority;
- platform approval→legal/brand truth.

25. RECONCILIATION DISPOSITION


KEEP / CORE CANDIDATE:
- Brand is scoped truth/readiness layer, not Strategy/Creative engine;
- Brand Truth/Asset/Proof/Derivative/Campaign Creative distinctions;
- business/brand scope isolation;
- explicit inheritance only;
- Source/Master/Derivative/Usage lineage;
- Rights≠Consent≠Provenance;
- intended-use-specific readiness;
- protected change/return principle;
- campaign-to-brand candidate not auto-promotion;
- Missing Asset job-first alternatives;
- Preserve What Works.


EXPAND:
- Brand Snapshot semantics;
- external professional access/return evidence;
- campaign-derived candidate lineage;
- rights/consent/privacy maturity and revocation;
- multi-business separation.


MERGE:
- Proof Asset claim-fit logic with shared Proof/Trust professional knowledge while Brand retains asset/readiness/rights view.


KEEP WORKING / ARCHITECTURE:
- exact readiness states;
- exact Brand schema;
- exact inheritance modes;
- exact protected list;
- exact retention/export;
- exact Advisor/Creative/Production contracts;
- provenance technology.


REJECT AS CORE TRUTH:
- single readiness score;
- fixed asset checklist/count;
- auto-inheritance;
- auto-promotion;
- binary “rights=yes” field;
- strategy-by-existing-assets.
